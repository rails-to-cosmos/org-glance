#+TITLE: Global invariants
#+DATE: 2026-07-18

Rules the whole codebase enforces; every change must preserve them.  Each entry:
the rule, where the code enforces it (symbol anchors, stable across refactors),
and what breaks on violation.  Compact index in [[file:../CLAUDE.md][CLAUDE.md]].

* Store

1. *Append-only WAL, positional last-wins.*  Duplicate ids resolve by physical
   position (oldest→newest segments, last line wins); =seq= is a storage-only
   ordinal — never read for ordering, never in headline metadata, never
   re-stamped by compaction.  Enforced: =org-glance-graph--latest-records=,
   =org-glance-graph--heal=.  Violation: union-merged stores resolve the wrong
   record; heal misclassifies debris.

2. *Atomic writes; MANIFEST swap is the commit point.*  Every store write is
   temp-then-rename (=org-glance-graph--atomic-write=, =file-precious-flag= on
   blobs); compaction commits the MANIFEST *before* truncating the open segment.
   Violation: crash/ENOSPC truncates data or resurrects a tombstoned headline.

3. *MANIFEST byte-stability.*  A valid MANIFEST is never rewritten; rebuilt only
   when broken (=org-glance-graph--manifest-broken?=).  Violation: churn that
   fights compaction and generates sync conflicts.

4. *Schema tables are the single source of truth.*
   =org-glance-headline-metadata:fields= drives constructor + serialize +
   deserialize (load-time guard against the struct; row order IS the JSON key
   order — append new fields at the end only); =org-glance-filter:table= drives
   keys + predicate + canonicalisation.  Violation: silent drift (always-nil
   field, match-everything filter) or broken on-disk byte order.  A list-valued
   field MUST encode to a JSON *vector* (=org-glance-graph--encode= builds
   =vector=s): =--append= calls =json-serialize= OUTSIDE the error-demoted hook,
   so a nil/list encoder crashes *every* save — and the load-time guard checks
   slot ORDER, not encode kinds, so it will not catch this.

5. *Canonical blobs, derived indexes.*  =data/<id>/data.org= is canonical;
   metadata, caches and sidecars are rebuildable (=org-glance-reindex=).  Write
   ordering: metadata computed first (fail before any write), blob before WAL
   append (=org-glance-graph:add=).  The property index
   (=cache/property-index.eld=) is a PURE derived cache: every read is
   content-hash-guarded with an O(N) blob-parse fallback, a gone id is never
   cached, and =org-glance-reindex= drops it — so no caller may trust an index
   value in a durable write/delete without that fallback
   (=org-glance-property-index--entry=).  The content hash covers what the
   headline SAYS: the id/hash bookkeeping properties
   (=org-glance-headline:hash-ignore-properties=) and the LOGBOOK drawers
   (=org-glance-headline:hash-ignore-drawers=) are stripped before hashing, so
   clocking in and out never churns the hash or the caches keyed on it --
   nothing derived reads the logbook.  Relation edges follow the same rule:
   the =org-glance-material:= body link is canonical; the =relations= AND
   =links= metadata fields are projections recomputed on save/reindex — never
   written independently of content.  Occurrence snapshots (=data/<id>/occurrences/=)
   are canonical content too — immutable files GC'd with the id dir, never
   indexed state (GC runs at compaction, so a tombstoned id's snapshots linger
   until then).  Violation: unrebuildable facts or half-states.

6. *Path safety before filesystem.*  An id is checked (reject empty, =/= and
   =..=) via =error= — never =cl-assert=, which can be compiled out — before
   feeding any path (=org-glance-graph:headline-data-path=).  Violation: a
   hand-edited id escapes the store (traversal; an empty id resolves to the
   data root, which compaction GC would delete).

7. *Single user, no locking.*  Cross-process staleness is detected by the store
   snapshot — open-segment mtime + SIZE + sealed-segment NAME list, never mtime
   alone (=org-glance-graph--store-snapshot=); in-process mutations call
   =--invalidate-cache= explicitly.  Violation: same-second external compaction
   serves deleted data as live.  Two Emacsen folding one =EXTERNAL.jsonl= need
   no lock all the same: inv 34 leaves them nothing to serialise, the fold
   moving a cursor where it used to rewrite the file.

8. *Git conflicts heal by union merge.*  Gated by
   =org-glance-conflict-resolution= (ask/union/nil); =.gitattributes= written
   only if absent; =.eld= sidecar merges are commutative and non-inflating —
   earliest/latest/=max=, never a sum; a =nil= side never shadows a populated
   one (=org-glance--read-eld=, =org-glance-tag-metrics--merge-plists=).  The
   property-index sidecar is the deliberate exception — it reads via the lossy
   =--read-eld= floor, NOT a union, because a conflict self-heals on the next
   content-hash miss.  See
   [[file:proposals/2026-07-15-eld-sidecar-conflict-resolution.done.org][eld-sidecar-conflict-resolution]].

* Hooks and views

9. *Soft paths are error-demoted.*  Side-index hooks
   (=org-glance-graph-before-append-functions=,
   =org-glance-graph-after-open-functions=), view refresh, the occurrence
   snapshot (=org-glance-material:snapshot-on-repeat=) and the PLUGIN loader
   (=org-glance--load-plugins=) all run under demoted errors — a sidecar, a
   reload or a third-party plugin may never break a save, an open, a display
   or init.  The deliberate loud counterpart is =org-glance-plugin-enable=:
   an explicit enable reports its failure.

10. *PUSH-flag + PULL-refresh coherence.*  A save only flags open views stale
    (boolean; no I/O, never touches point); views re-fill at display boundaries;
    freshness checks are strict — when in doubt, rebuild (serving stale is the
    only real bug).  Enforced: =org-glance-view=, =org-glance-material:sync=.

11. *Never clobber unsaved edits.*  Any operation rewriting a blob open in a
    modified buffer must =user-error= or skip that row
    (=org-glance-material--replace-headline=, =:retag= — its =user-error= trapped
    by the table's =org-glance-table--act-deltag=, bulk todo); a modified
    file-backed view is flagged stale, never reverted.  Deletion
    (=org-glance-material:delete=) names unsaved edits in its consent prompt
    and tombstones BEFORE discarding the buffer, so a failed append never
    costs the only unsaved copy.  The external fold discards nothing, having
    no human to ask; the accepted cost is
    [[*H2 -- a folded delete is undone by the id's open material buffer][H2]].

* Parsing and data hygiene

12. *Store content parses in temp buffers via =org-glance--org-mode=.*
    =delay-mode-hooks= (no globalized minor modes, no undo-tree litter) and
    =tab-width 8= set after mode init; sources are never =find-file='d for
    reading.  Violation: user =tab-width= mis-parses content; hook litter.

13. *Tags are canonical downcased interned symbols; relation kinds are
    canonical dash-slugs.*  Kinds slug (downcase, spaces→dashes) at EVERY
    boundary — link encode, link decode, metadata deserialize
    (=org-glance--kind-slug=); the spaced form is display-only.  Tags:  Coerced via
    =org-glance-tag:from-string= wherever text enters; serialized back to
    strings in metadata (so deserialized metadata carries STRING tags — coerce
    with =(downcase (format "%s" tag))= when comparing, or read through
    =org-glance-headline-metadata:tag-strings=, the one total coercion).
    Case-twins collapse at every boundary: parse
    (=org-glance-headline--from-element= dedupes), read (=tag-strings=
    downcases + dedupes legacy records), retag compares canonically, and the
    material save collapses =:Food:food:= in the heading itself
    (=org-glance-material--dedupe-tags=).  Validation
    (=org-glance-tag:validate-string=, org's tag grammar) runs ONLY at
    creation boundaries — capture prompt, programmatic capture, retag add —
    never on read or removal, so legacy tags stay loadable and removable.
    Violation: mixed-case duplicates fragment filters and caches, or a stored
    tag becomes untouchable.

14. *Crypt: plaintext never touches disk; secrecy is per-block.*  An
    encrypted headline materializes SEALED (ciphertext, no prompt, no
    hardening -- nothing secret is in the buffer yet); decryption is
    explicit (=C-c #= on a sealed buffer, =org-glance-material:decrypt=,
    or =:open ... :decrypt t=) and hardens the buffer BEFORE any plaintext
    lands -- including the unwrap path (=org-glance-material:crypt-unwrap=
    wires first).  =C-c #= on a decrypted buffer seals it back
    (=org-glance-material:seal=), which refuses while edits are unsaved so
    ciphertext never hides them (invariant 11).  Decrypted buffers are
    hardened (no auto-save/backup/lockfiles),
    sealed by =before-save-hook=, unsealed after; =#+begin_crypt= markers are the
    persistent secrecy annotation, and the legacy upgrade cannot re-wrap
    plaintext (aes-header guard in =org-glance-headline--crypt-upgrade-legacy=).
    Only block bodies are secret: text OUTSIDE the blocks stays plaintext on disk
    and IS indexed even for an =encrypted?= headline (so its links/properties
    resolve, and the index never holds decrypted plaintext).  Occurrence
    snapshots are plaintext: an encrypted material buffer never snapshots
    (=org-glance-material:snapshot-on-repeat=), and BOTH encrypt paths purge
    existing snapshots (=org-glance-material--purge-occurrences=).  The
    =links=/=relations= projections compute from SEALED bytes, so a link
    inside a crypt block is never indexed; capture of content already
    carrying UNSEALED =#+begin_crypt= markers indexes it as the plaintext it
    is — markers bind through the material/crypt-set flows only.  Violation:
    secrets leak to =data.org= / backups / =occurrences/=, or an encrypted
    headline's intentionally-public regions vanish from search.

* Views and tables

15. *Table Title column is mandatory.*  Never removable or hideable —
    =org-glance-table--mandatory-column?= is the single spelling of the rule --
    =:remove-column= refuses it (at point or by name), =--read-column= never
    offers it, =--compose-columns= strips it from any hidden set, and
    =org-glance-table--compose-columns= (shared by the per-tag schema and the
    scoped reference layouts) strips =title= from the hidden set
    (defence in depth against a hand-edited sidecar).  Violation: rows lose their
    only human-readable label; a schema file could blank every view of a tag.

16. *Per-tag column schema: hidden is a denylist; candidates are user keys.*  The
    per-tag =:hidden= set records REMOVED built-ins (=table-columns.eld=), never
    an allowlist of the visible set — so a built-in shipped in a later version
    still appears; the =C-c += candidate keys exclude =ORG_GLANCE_*= bookkeeping
    and org's synthesised =CATEGORY= (=org-glance-property-index--candidate-key?=).
    Column order + sort persist separately, per filter (=table-views.eld=).
    Violation: a version upgrade's new column is invisible to anyone with a saved
    schema; internal keys pollute the column prompt.

17. *Transient filters never persist per-filter state.*  Keys flagged
    =:transient= in =org-glance-filter:table= (=:where=, =:refers-to=,
    =:id-any=) are one-off views: the overview never caches them
    (=org-glance-overview:spec-key= → nil), and the table persists neither
    their view config (=org-glance-table--persist-config=) nor their column
    schema (=org-glance-table--persist-schema= — a tagless relation view would
    edit the shared \":none:\" entry).  Judged by the single predicate
    =org-glance-filter:transient?=.  Violation: one cache dir / config entry
    accretes per visited headline (=:id-any= identities embed the target
    snapshot — one per link-set version), with no pruning pass to reclaim
    them.  EXPLICIT scoped persistence is the sanctioned exception: =C-c C-c=
    in a reference table (=org-glance-table:apply-layout=) saves the
    layout under a user-chosen scope key (anchor id or tag pair, per
    direction) in =table-refs.eld= — never under the filter identity, one
    entry per deliberate apply, so browsing still accretes nothing.

18. *Scoped relation layouts: out-of-band identity, id > pair, whole-set
    replace.*  The anchor travels as =:context= into =org-glance-table:visit=
    — never reconstructed from the filter, which has lost it.  Resolution
    (=org-glance-table--refs-resolve=): the anchor's own entry beats tag
    pairs; among pairs the latest =:applied= stamp wins.  A scoped entry
    REPLACES the whole column set built from base columns — it never merges
    with =table-columns.eld= — and a scope-less relation view renders plain
    defaults, never the shared untagged ":none:" schema entry.  A relation
    table lists BOTH directions in one view (=org-glance-table--related-ids=),
    so pair keys read anchor tag > row tag — scope, never edge direction —
    single-sourced in =org-glance-table--refs-tag-pairs=; the mirrored pair
    (anchored on the other side) is a DIFFERENT scope.  Pair tags are sorted,
    distinct, downcased (mirrors inv 13).  =table-refs.eld= is written only on
    explicit =C-c C-c=, so a git conflict drops one side with no self-healing
    rewrite (unlike the constantly-rewritten auto-persisted stores).
    Violation: saved layouts that never match on restore, cross-scope leaks,
    nondeterministic pair resolution.

19. *The table is a pure projection; every mutation routes through the
    material layer.*  All =org-glance-table--act-*= handlers delegate to
    =org-glance-material:= functions (todo, bulk todo, retag, crypt, delete, planning,
    title/priority/property edits, duplicate) — no table-originated write touches store, blob, or metadata
    directly, and bulk operations degrade per-row (skip-and-report), never
    batch-abort.  Violation: bypasses the unsaved-edit guard (inv 11) and
    the blob-canonical rule (inv 5).

20. *Overview headings are self-sufficient, metadata-only.*  The render
    (=org-glance-overview:render-headline=) carries state, priority cookie,
    the SINGLE planning line, the id drawer, the verbatim date-interval line
    (=<from>--<to>=, so agenda shows the span), relations and plain links —
    all from metadata, zero blob parses; agenda and link-following work
    without materializing.  Violation: agenda misses planning, or the render cost
    becomes O(blobs).

21. *Reserved properties are managed keys.*  The keys in
    =org-glance-material-hidden-properties= belong to org-glance:
    concealed in material buffers (overlays only — file and store keep them),
    and hand edits to them reverted at =before-save= with a warning
    (=org-glance-material--restore-reserved= — the sole sanctioned in-buffer
    edit under invariant 11; it touches only the heading drawer, disjoint from
    the crypt seal's body blocks).  Violation: a hand-edited or region-killed
    =ORG_GLANCE_ID= silently orphans the blob from its WAL id.

22. *Material saves rewrite user content only through announced normalize
    hooks.*  The =before-save-hook= rewrites are exactly: the reserved-property
    revert (=org-glance-material--restore-reserved=), the case-twin tag
    collapse (=org-glance-material--dedupe-tags=) — each raising a
    =display-warning= — and the crypt seal (invariant 14).  Violation: a
    silent rewrite clobbers user text with no trace (collides with inv 11).

23. *LLM session state is derived live, never persisted.*  Running /
    exited / stopped, buffer names and titles all recompute at fill
    (=org-glance-llm--session-rows=) from two cheap sources: the provider's
    recorded sessions filtered to this graph's data dirs (=--recorded=,
    O(recorded)) for the historical =stopped= rows, overlaid with live
    =*llm:…*= buffers for running/exited state.  Nothing persists and
    nothing scans the whole graph, so there is no cache to go stale.
    Violation: a killed buffer shows "running", a restarted one "stopped",
    or a stored row is trusted for anything live.  (The enforcing symbols
    live in the external =org-glance-llm= plugin repo, loaded via
    =org-glance-plugins=; this invariant governs that plugin's contract,
    not core.  =org-glance-graph:cache-read= / =:cache-write= remain the
    public sidecar API for a plugin that does want a derived, rebuildable
    cache under =cache/= — invariant-5 class, dropped by reindex.)

24. *Table point restoration restores the CELL — row AND column.*  Every
    refill captures =org-glance-view:point-context= (ID LINE COL) and
    restores through =org-glance-view:restore-point=, which re-lands on the
    same cell by its =table-view-col= key; a row that left the view falls
    back to its screen line.  Both tables obey it — the headline table's
    =--finish= / =--reload= / bulk-todo paths and the LLM sessions table's
    =g=.  Violation: the cursor drops to column 0, where the next =i= (edit
    cell) or =C-c -= (remove column) acts on the WRONG column.

25. *Links are addressed by their list path; the link's own item label is
    dropped.*  =org-glance--link-paths= gives every link a PATH of enclosing
    plain-list item labels plus its own LABEL (=org-glance--link-label=): its
    description, else the =KEY:= text introducing it in its own item
    (=- Local: [[file:~/x]]= reads "Local" — a bare link takes its meaning
    from that text, and the raw URL is a poor label), else the raw link.
    =org-glance--link-ancestry= drops the innermost item (the label already
    names it), and a link outside any list gets a one-element path,
    so flat and nested bodies share one representation.
    =org-glance--pick-link-pos= descends one component per prompt, takes a
    lone candidate at any depth without asking, and offers exhausted-path
    ties by TARGET — without that base case identical paths recurse forever.
    Violation: every leaf becomes a one-option prompt, or the picker hangs.

26. *Plugins load error-demoted, self-register, and never unload.*  A plugin
    is =org-glance-<name>.el= listed in =org-glance-plugins= and =require=-d
    by =org-glance--load-plugins= (inv 9) before the graph opens; it appends
    its own transient entries at load (remove-then-append, so a reload never
    duplicates) and binds its own keys.  There is no unload protocol:
    disabling = dropping it from the list and restarting.  Violation: a
    broken third-party plugin bricks =org-glance-init=, or reloading
    duplicates its UI.

* Confirmed by the 2026-07-26 sweep

Rules the code already enforced without being written down here.  Each was
verified against its evidence site before being added.

27. *Save-hook depth ordering is load-bearing.*  =org-glance-material:sync=
    runs at depth 0, =--decrypt-buffer= at 90, =--hide-reserved-properties=
    at 100, so =sync= reads the buffer while it is still SEALED and the WAL,
    the property index and every projection see ciphertext.  This is the
    concrete mechanism behind invariant 14's "plaintext never touches disk".
    Violation: lowering =--decrypt-buffer= below =sync= indexes decrypted
    plaintext into =headlines.jsonl= and the property cache.

28. *Multi-block crypt rewrites iterate LAST to FIRST.*  Both
    =org-glance--crypt--transform-blocks= and =--crypt-unwrap-blocks= walk
    =(reverse (block-regions))=: any length-changing rewrite invalidates the
    recorded positions of blocks after it.  Violation: a headline with two or
    more =#+begin_crypt= blocks is corrupted on seal/unseal.

29. *org's =ARCHIVE= marker is never a collection tag.*
    =org-glance-headline--from-element= removes it from the parsed tag set
    (the =archived?= flag carries it).  Violation: a phantom =archive= tag
    appears in =graph:tags=, the capture picker and every per-tag view, over
    headlines the ambient filter hides.

30. *=graph:get-headline= is tri-state: nil / =tombstone= / metadata.*
    Read-only callers collapse the first two through
    =org-glance-graph:live-meta=.  Two callers need the distinction, and they
    share one guard: =org-glance-graph--tombstone-spec= answers the record a
    delete owes or nil, for =org-glance-graph:delete= (which appends it alone)
    and for =org-glance-graph:refresh-external= (which carries it into the one
    batch its whole fold appends).  Violation: collapsing tombstone to nil
    resurrects deleted ids in derived indexes and appends duplicate tombstones;
    spelling the guard twice lets the two drift.

31. *=org-glance-material= must never top-level =require= =org-glance-table=.*
    The dependency runs table -> material; the relation pivot
    (=org-glance-material:references=) requires table at CALL time.
    Violation: a circular load that breaks byte-compilation and init.

32. *Torn-line tolerance is scoped to the open segment's FINAL line.*
    =org-glance-graph--scan-file= swallows a =json-error= only for the last
    line of the open segment and re-signals everywhere else.  Violation:
    tolerating a torn line mid-file silently masks real store corruption.

33. *An external writer announces moved and deleted blobs; READS fold them in.*
    The =glance= daemon appends =\{"id":…,"at":…\}= lines to
    =meta/EXTERNAL.jsonl= (=O_APPEND=, whole lines) and touches nothing else
    under =meta=; a DELETE is those two fields plus ="tombstone":true=, the
    only third field and the only value it takes, so a line's absence of it IS
    the write.  =org-glance-graph--read-external= keeps ONE entry per id at its
    first sighting carrying its LAST sighting's kind (=--latest-records='' own
    rule), so a write followed by a delete in one window folds as the delete;
    the kind test is =(eq t …)=, since =json-parse-string= maps JSON false and
    null to the non-nil =:false= and =:null=.  An unknown key is inert both
    ways: a new =glance= against an old org-glance degrades to a skipped
    ="no stored blob"=, and an old =glance= writes no third field at all.
    Every read folds the pending entries through
    =org-glance-graph--fold-external-maybe= (=--ensure-cache=), so an outside
    edit needs no command.  The fold is throttled
    (=org-glance-graph-external-poll-seconds=, one stat per graph per
    interval), non-reentrant (=--folding-external=, bound by
    =refresh-external= itself so its own reads cannot nest) and
    =condition-case='d, so it can neither loop nor break a read under
    =debug-on-error=.  The whole batch — re-derived records and tombstones
    alike — is ONE =graph:insert=; the fold's cursor moves only AFTER that
    append (the crash rule: a repeated write costs an equal record the
    latest-per-id fold cannot distinguish, and a repeated delete finds the id
    already tombstoned and appends nothing).  Violation: reversing the two
    steps loses an edit outright; per-id inserts break the one-append rule the
    crash argument rests on; folding inside a fold recurses; an unguarded
    signal takes a plain read down with it.  What this fold gives up is written
    below as [[*Known hazards][H2]].

* Added 2026-08-12

34. *The fold moves a CURSOR; it never rewrites =EXTERNAL.jsonl=.*
    =meta/EXTERNAL.cursor= holds one decimal BYTE offset — how far this store
    has folded — and =org-glance-graph--read-external= reads from there to the
    end of the file (=insert-file-contents= with byte BEG/END).  BYTES because
    the writer appends bytes where Emacs reads characters, and whole lines are
    what a fold consumes, so the offset always lands where decoding can start;
    the two spaces never have to agree.  =--set-external-cursor= writes it
    temp-then-rename after the records land (inv 33's crash rule).  THE READER
    MUTATING NOTHING is what makes two Emacsen folding one store safe with no
    lock — invariant 7 stands, with nothing to serialise rather than with a
    guarded mutation.  Both folding one range appends two equal records, the
    crash rule's own idempotence, and a cursor written BACKWARDS costs the same
    re-fold; it is deliberately NOT guarded with =max=, forwards being the
    direction that skips lines and =max= being what would make a number past
    the bytes that exist stick.  What guards THAT is the read: a cursor absent,
    garbled or PAST the file's end reads as 0.

    GROWTH IS ROTATION (=--rotate-external-maybe=), never truncation.  Once the
    file passes =org-glance-graph-external-max-bytes= AND the cursor has caught
    up, the cursor is renamed to =EXTERNAL-<gen>.cursor= and the file to
    =EXTERNAL-<gen>.jsonl= — cursor first, since a generation with no cursor is
    re-folded whole (a no-op) where a fresh live file under the old cursor would
    have its first lines skipped.  The daemon's next append creates the live
    file again, opening the path per line (=Data.Org.External.appendLine=,
    =O_CREAT|O_APPEND=), so a rename between its open and its write lands that
    line in the ROTATED file — which still exists, is drained ahead of the live
    one, and is NEVER deleted on the pass that made it: the older generation
    goes at the START of the next rotation, so at most two are on disk and each
    outlives any in-flight open.  This is the store's own shape one file over,
    where the open WAL segment is appended to and sealed by a rename (inv 2).

    Violation: rewriting the file at all reopens the race H1 names — a fold
    dropping what another already took eats the head of whatever arrived
    between, and a lost tombstone never self-heals, the blob being gone.
    Trusting a cursor past EOF skips lines nothing read.  Unlinking a
    generation on the pass that rotated it loses the line an in-flight open is
    about to write.  Rejected: a lock across Emacsen (invariant 7, and it buys
    nothing here — there is no mutation to serialise) and shortening the file
    under any guard, since =f-write-text= is =write-region= with =append= nil
    and destroys whatever the daemon appended between its own read and its own
    write.

* Known hazards

Costs the code ships WITH, deliberately.  An invariant is a rule a change must
preserve; a hazard is what today's design gives up, so it is lettered and kept
apart -- a reader meeting the symptom should find the decision written down.
Each was reproduced with a probe before being added, and each earns a test in
[[file:../test/test-external.el][test-external.el]] pinning today's behaviour,
so closing one turns its own case red and names the decision.  An OPEN entry
states what it costs, what would close it, and why it stands.  A letter is never
reused, and a CLOSED entry keeps its place so the symptom stays findable: what
it states instead is what the symptom was, what closed it, and which cases now
hold the rule.

** H1 -- CLOSED 2026-08-12: the external fold's truncate race ate a tombstone

*The symptom.*  =org-glance-graph--truncate-external= rewrote the file with a
character COUNT dropped from its head, counted against the file the fold had
read.  Invariant 7 gives two Emacsen folding one store no lock, so the second
truncate ate the head of whatever landed between -- measured: E2 reads 74
characters, E1 folds and empties, the writer appends the 91-character tombstone,
E2 truncates by 74 and leaves =tombstone":true}=, with the record LIVE and the
fragment surviving every later fold.  A lost write note self-heals, the blob
still being the truth; a lost TOMBSTONE never does, the blob having gone, so no
later edit will ever name that id again.

*Why a guarded mutation did not close it.*  A compare-and-swap on the prefix
narrowed the window and left an inner one: =f-write-text= is =write-region= with
=append= nil, so a line the daemon appends between that function's own
=f-read-text= and its own =f-write-text= is destroyed -- H1's exact symptom,
reachable with ONE Emacs.  Guarding a mutation cannot close a race against an
appender.

*Closed by invariant 34*, which removes the mutation: the fold reads from a byte
cursor and writes that cursor forward, and growth is handled by rotation.  There
is no window because there is no rewrite.  Pinned by
=external-race-spares-the-tombstone=,
=external-keeps-a-note-that-arrived-mid-fold=,
=external-keeps-a-byte-identical-note=, =external-double-fold-is-a-no-op=,
=external-a-lost-cursor-refolds-from-zero=,
=external-a-cursor-past-the-end-refolds= and the three rotation cases.

*The residual is gone with it.*  Under the swap, a note arriving byte-identical
to the text a fold read was indistinguishable from it and was dropped with it.
An OFFSET counts bytes rather than comparing them, so the second note survives
-- which is what =external-keeps-a-byte-identical-note= asserts, the opposite of
the case that pinned the residual.

** H2 -- a folded delete is undone by the id's open material buffer

=org-glance-material:delete= discards the id's open material buffer, naming
unsaved edits in its consent prompt (invariant 11).  The fold's tombstone arm
inserts the spec and touches no buffer, so that buffer survives a folded delete
and the next save's =org-glance-material:sync= appends a LIVE record over the
tombstone.

Reproduced (=external-delete-is-undone-by-an-open-buffer=), both ways: with the
blob directory left standing the save is silent; with it removed -- as the
daemon leaves it -- the save asks org's own "Directory does not exist; create?"
and a =yes= puts the blob back too.  A =no= aborts the save, so
=after-save-hook= never runs and the tombstone stands: the record and the blob
never come back apart.  What does not come back is the blob's occurrence
history, canonical content under invariant 5, which went with the directory.

- *Costs:* one live record and one recreated blob per delete of an id somebody
  had open, minus that id's =occurrences/=.  The record and the document come
  back together, so no store-level counter moves in the ordinary interleaving.
  It IS visible in one: a save landing BEFORE the fold reads leaves the
  tombstone standing over a blob back on disk, which =glance='s scan counts as
  an unindexed blob (=Data.Org.Index.driftOf=, =dfUnindexed=) -- pinned as
  =external-delete-after-a-save-strands-the-blob=.  Deleting the resurrected id
  through =glance= again is refused, its trash destination already holding that
  id (=Data.Org.Trash=, "the trash already holds"); =M-x org-glance-delete=
  clears the record.
- *Would close it:* discarding the buffer in the tombstone arm, as
  =material:delete= does; or discarding only CLEAN buffers and leaving a dirty
  one with a warning.
- *Open because:* a fold runs in the BACKGROUND, off any read, and
  =material:delete='s consent-when-dirty guard exists precisely because
  discarding a dirty buffer needs a human.  Silently discarding one during a
  background fold breaks invariant 11 -- never clobber unsaved edits -- to save
  a record =M-x org-glance-delete= clears in one command.  The resurrected
  record is the lesser harm.
