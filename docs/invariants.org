#+TITLE: Global invariants
#+DATE: 2026-07-18

Rules the whole codebase enforces; every change must preserve them.  Each entry: the
rule, the symbol anchors enforcing it, what breaks on violation, and the measurements
and reproductions that pin it.  Compact index in [[file:../AGENTS.md][AGENTS.md]];
argument in [[file:proposals][docs/proposals/]].

* Store

1. *Append-only WAL, positional last-wins.*  Duplicate ids resolve by physical position
   (oldest→newest segments, last line wins); =seq= is storage-only — never ordering,
   never in headline metadata, never re-stamped by compaction.  Enforced:
   =org-glance-graph--latest-records=, =org-glance-graph--heal=.  Violation:
   union-merged stores resolve the wrong record; heal misclassifies debris.

2. *Atomic writes; MANIFEST swap is the commit point.*  Every store write is
   temp-then-rename (=org-glance-graph--atomic-write=, =file-precious-flag= on blobs);
   compaction commits the MANIFEST *before* truncating the open segment.  Violation:
   crash/ENOSPC truncates data or resurrects a tombstoned headline.

3. *MANIFEST byte-stability.*  A valid MANIFEST is never rewritten; rebuilt only when
   broken (=org-glance-graph--manifest-broken?=).  Violation: churn that fights
   compaction and generates sync conflicts.

4. *Schema tables are the single source of truth.*
   =org-glance-headline-metadata:fields= drives constructor + serialize + deserialize;
   row order IS the JSON key order, so new fields append at the END only, and the
   load-time guard checks slot ORDER against the struct.  =org-glance-filter:table=
   drives keys + predicate + canonicalisation.  A list-valued field MUST encode to a
   JSON *vector* (=org-glance-graph--encode= builds =vector=s): =--append= calls
   =json-serialize= OUTSIDE the error-demoted hook, so a nil/list encoder crashes
   *every* save.  Violation: silent drift (always-nil field, match-everything filter),
   broken on-disk byte order, an unsaveable store.

5. *Canonical blobs, derived indexes.*  =data/<id>/data.org= is canonical; metadata,
   caches and sidecars are rebuildable (=org-glance-reindex=).  Write order: metadata
   first (fail before any write), blob before WAL append (=org-glance-graph:add=).  The
   property index (=cache/property-index.eld=) is a PURE derived cache — every read
   content-hash-guarded with an O(N) blob-parse fallback
   (=org-glance-property-index--entry=), a gone id never cached, dropped by
   =org-glance-reindex=; never trust an index value in a durable write/delete without
   that fallback.  The content hash strips the id/hash properties
   (=org-glance-headline:hash-ignore-properties=) and the LOGBOOK drawers
   (=org-glance-headline:hash-ignore-drawers=), so clocking never churns it or the
   caches keyed on it.  The =org-glance-material:= body link is canonical; =relations=
   AND =links= metadata are projections recomputed on save/reindex.  Occurrence
   snapshots (=data/<id>/occurrences/=) are canonical content — immutable, GC'd with
   the id dir at compaction, so a tombstoned id's snapshots linger until then.
   Violation: unrebuildable facts or half-states.

6. *Path safety before filesystem.*  An id is checked (reject empty, =/= and =..=) via
   =error= — never =cl-assert=, which can be compiled out — before feeding any path
   (=org-glance-graph:headline-data-path=).  Violation: a hand-edited id escapes the
   store (traversal; an empty id resolves to the data root, which compaction GC would
   delete).

7. *Single user, no locking.*  Cross-process staleness is detected by the store
   snapshot — open-segment mtime + SIZE + sealed-segment NAME list, never mtime alone
   (=org-glance-graph--store-snapshot=); in-process mutations call =--invalidate-cache=
   explicitly.  Violation: same-second external compaction serves deleted data as live.
   Two Emacsen folding one =EXTERNAL.jsonl= need no lock: inv 34 leaves them nothing to
   serialise.

8. *Git conflicts heal by union merge.*  Gated by =org-glance-conflict-resolution=
   (ask/union/nil).  THE RESOLVER IS THE WAL'S AND NAMES IT POSITIVELY:
   =--conflicted-jsonl-files= takes the open segment and the sealed =seg-<gen>.jsonl=
   and nothing else, so every other JSONL family under =meta/= is out by construction —
   =EXTERNAL.jsonl=, its rotated generations (retired ones under =meta/spent/=
   included), glance's =COMPLETIONS.jsonl=.  The resolver's own
   =f-read-text=/=f-write-text= would re-lay the bytes a fold cursor measured (inv 34's
   second door).  The NAMES are the handle: the MANIFEST is unusable here, this running
   at open ahead of =--reconcile-manifest=.  A marker left in a notification file costs
   its own line and no others, the fold skipping what no JSON reader can parse.
   Measured: opening a graph over a 1 MiB notification file, 2.2 ms with the rule and
   31.1 ms without.

   =.gitattributes= is written only if absent, naming THE SAME TWO PREDICATES —
   =headlines.jsonl= and =seg-*.jsonl= — so the allowlist reaches the rule git obeys
   and not only the reader; a =*.jsonl= glob gave the union driver every excluded
   family, on the one cohort =--ensure-gitignore= cannot help (inv 34).  A store
   already carrying the wide glob keeps it until a hand edit.

   =.eld= sidecar merges are commutative and non-inflating — earliest/latest/=max=,
   never a sum; a =nil= side never shadows a populated one (=org-glance--read-eld=,
   =org-glance-tag-metrics--merge-plists=).  The property-index sidecar is the
   deliberate exception, reading via the lossy =--read-eld= floor, a conflict
   self-healing on the next content-hash miss.  See
   [[file:proposals/2026-07-15-eld-sidecar-conflict-resolution.done.org][eld-sidecar-conflict-resolution]].

* Hooks and views

9. *Soft paths are error-demoted.*  Side-index hooks
   (=org-glance-graph-before-append-functions=,
   =org-glance-graph-after-open-functions=), view refresh, the occurrence snapshot
   (=org-glance-material:snapshot-on-repeat=) and the PLUGIN loader
   (=org-glance--load-plugins=) run under demoted errors — a sidecar, a reload or a
   third-party plugin may never break a save, an open, a display or init.  The
   deliberate loud counterpart is =org-glance-plugin-enable=.

10. *PUSH-flag + PULL-refresh coherence.*  A save only flags open views stale (boolean;
    no I/O, never touches point); views re-fill at display boundaries; freshness checks
    are strict — when in doubt, rebuild.  Enforced: =org-glance-view=,
    =org-glance-material:sync=.  Violation: serving stale is the only real bug.

11. *Never clobber unsaved edits.*  Any operation rewriting a blob open in a modified
    buffer must =user-error= or skip that row (=org-glance-material--replace-headline=,
    =:retag= — its =user-error= trapped by the table's =org-glance-table--act-deltag=,
    bulk todo); a modified file-backed view is flagged stale, never reverted.
    =org-glance-material:delete= names unsaved edits in its consent prompt and
    tombstones BEFORE discarding the buffer, so a failed append never costs the only
    unsaved copy.  The external fold discards nothing, having no human to ask; the
    accepted cost is
    [[*H2 -- a folded delete is undone by the id's open material buffer][H2]].

* Parsing and data hygiene

12. *Store content parses in temp buffers via =org-glance--org-mode=.*
    =delay-mode-hooks= (no globalized minor modes, no undo-tree litter) and =tab-width
    8= set after mode init; sources are never =find-file='d for reading.  Violation:
    user =tab-width= mis-parses content; hook litter.

13. *Tags are canonical downcased interned symbols; relation kinds are canonical
    dash-slugs.*  Kinds slug (downcase, spaces→dashes) at EVERY boundary — link encode,
    link decode, metadata deserialize (=org-glance--kind-slug=); spaced form is
    display-only.  Tags coerce via =org-glance-tag:from-string= wherever text enters
    and serialize back to strings, so deserialized metadata carries STRING tags —
    compare with =(downcase (format "%s" tag))= or read through
    =org-glance-headline-metadata:tag-strings=, the one total coercion.  Case-twins
    collapse at every boundary: parse (=org-glance-headline--from-element= dedupes),
    read (=tag-strings= downcases + dedupes legacy records), retag compares
    canonically, material save collapses =:Food:food:= in the heading
    (=org-glance-material--dedupe-tags=).  Validation (=org-glance-tag:validate-string=,
    org's tag grammar) runs ONLY at creation boundaries — capture prompt, programmatic
    capture, retag add — never on read or removal.  Violation: mixed-case duplicates
    fragment filters and caches, or a stored tag becomes untouchable.

14. *Crypt: plaintext never touches disk; secrecy is per-block.*  An encrypted headline
    materializes SEALED (ciphertext, no prompt, no hardening); decryption is explicit
    (=C-c #= on a sealed buffer, =org-glance-material:decrypt=, =:open ... :decrypt t=)
    and hardens the buffer BEFORE any plaintext lands, the unwrap path included
    (=org-glance-material:crypt-unwrap= wires first).  =C-c #= on a decrypted buffer
    seals it back (=org-glance-material:seal=), refusing while edits are unsaved
    (inv 11).  Decrypted buffers are hardened (no auto-save/backup/lockfiles), sealed by
    =before-save-hook=, unsealed after; =#+begin_crypt= markers are the persistent
    secrecy annotation; the legacy upgrade cannot re-wrap plaintext (aes-header guard in
    =org-glance-headline--crypt-upgrade-legacy=).  Only block bodies are secret: text
    OUTSIDE the blocks stays plaintext on disk and IS indexed even for an =encrypted?=
    headline.  Snapshots are plaintext, so an encrypted material buffer never snapshots
    (=org-glance-material:snapshot-on-repeat=) and BOTH encrypt paths purge existing
    snapshots (=org-glance-material--purge-occurrences=).  The =links=/=relations=
    projections compute from SEALED bytes, so a link inside a crypt block is never
    indexed; capture of content already carrying UNSEALED =#+begin_crypt= markers
    indexes it as the plaintext it is — markers bind through the material/crypt-set
    flows only.  Violation: secrets leak to =data.org= / backups / =occurrences/=, or an
    encrypted headline's intentionally-public regions vanish from search.

* Views and tables

15. *Table Title column is mandatory.*  Never removable or hideable;
    =org-glance-table--mandatory-column?= is the single spelling — =:remove-column=
    refuses it (at point or by name), =--read-column= never offers it,
    =org-glance-table--compose-columns= (shared by the per-tag schema and the scoped
    reference layouts) strips =title= from any hidden set.  Violation: rows lose their
    only human-readable label; a schema file could blank every view of a tag.

16. *Per-tag column schema: hidden is a denylist; candidates are user keys.*  The
    per-tag =:hidden= set records REMOVED built-ins (=table-columns.eld=), never an
    allowlist of the visible set, so a built-in shipped later still appears; =C-c +=
    candidate keys exclude =ORG_GLANCE_*= bookkeeping and org's synthesised =CATEGORY=
    (=org-glance-property-index--candidate-key?=).  Column order + sort persist
    separately, per filter (=table-views.eld=).  Violation: a version upgrade's new
    column is invisible to anyone with a saved schema; internal keys pollute the column
    prompt.

17. *Transient filters never persist per-filter state.*  =:transient= keys in
    =org-glance-filter:table= (=:where=, =:refers-to=, =:id-any=) are one-off views: no
    overview cache (=org-glance-overview:spec-key= → nil), no table config
    (=org-glance-table--persist-config=), no column schema
    (=org-glance-table--persist-schema=; a tagless relation view would edit the shared
    ":none:" entry).  Judged by the single predicate =org-glance-filter:transient?=.
    Sole exception, EXPLICIT: =C-c C-c= in a reference table
    (=org-glance-table:apply-layout=) saves the layout under a user-chosen scope key
    (anchor id or tag pair, per direction) in =table-refs.eld= — never under the filter
    identity, one entry per deliberate apply.  Violation: one cache dir / config entry
    per visited headline (=:id-any= identities embed the target snapshot, one per
    link-set version), with no pruning pass to reclaim them.

18. *Scoped relation layouts: out-of-band identity, id > pair, whole-set replace.*  The
    anchor travels as =:context= into =org-glance-table:visit=, never reconstructed from
    the filter, which has lost it.  Resolution (=org-glance-table--refs-resolve=): the
    anchor's own entry beats tag pairs; among pairs the latest =:applied= stamp wins.  A
    scoped entry REPLACES the whole column set built from base columns, never merging
    with =table-columns.eld=; a scope-less relation view renders plain defaults, never
    the shared untagged ":none:" entry.  A relation table lists BOTH directions in one
    view (=org-glance-table--related-ids=), so pair keys read anchor tag > row tag —
    scope, never edge direction — single-sourced in
    =org-glance-table--refs-tag-pairs=; the mirrored pair is a DIFFERENT scope.  Pair
    tags are sorted, distinct, downcased (mirrors inv 13).  =table-refs.eld= is written
    only on explicit =C-c C-c=, so a git conflict drops one side with no self-healing
    rewrite.  Violation: saved layouts that never match on restore, cross-scope leaks,
    nondeterministic pair resolution.

19. *The table is a pure projection; every mutation routes through the material layer.*
    All =org-glance-table--act-*= handlers delegate to =org-glance-material:= functions
    (todo, bulk todo, retag, crypt, delete, planning, title/priority/property edits,
    duplicate) — no table-originated write touches store, blob or metadata directly —
    and bulk operations degrade per-row (skip-and-report), never batch-abort.
    Violation: bypasses the unsaved-edit guard (inv 11) and the blob-canonical rule
    (inv 5).

20. *Overview headings are self-sufficient, metadata-only.*  The render
    (=org-glance-overview:render-headline=) carries state, priority cookie, the SINGLE
    planning line, the id drawer, the verbatim date-interval line (=<from>--<to>=, so
    agenda shows the span), relations and plain links — all from metadata, zero blob
    parses; agenda and link-following work without materializing.  Violation: agenda
    misses planning, or the render cost becomes O(blobs).

21. *Reserved properties are managed keys.*  The keys in
    =org-glance-material-hidden-properties= belong to org-glance: concealed in material
    buffers (overlays only — file and store keep them), hand edits reverted at
    =before-save= with a warning (=org-glance-material--restore-reserved=, the sole
    sanctioned in-buffer edit under inv 11; it touches only the heading drawer, disjoint
    from the crypt seal's body blocks).  Violation: a hand-edited or region-killed
    =ORG_GLANCE_ID= silently orphans the blob from its WAL id.

22. *Material saves rewrite user content only through announced normalize hooks.*  The
    =before-save-hook= rewrites are exactly: the reserved-property revert
    (=org-glance-material--restore-reserved=), the case-twin tag collapse
    (=org-glance-material--dedupe-tags=) — each raising a =display-warning= — and the
    crypt seal (inv 14).  Violation: a silent rewrite clobbers user text with no trace
    (collides with inv 11).

23. *LLM session state is derived live, never persisted.*  Running / exited / stopped,
    buffer names and titles recompute at fill (=org-glance-llm--session-rows=) from two
    cheap sources: the provider's recorded sessions filtered to this graph's data dirs
    (=--recorded=, O(recorded)) for historical =stopped= rows, overlaid with live
    =*llm:…*= buffers for running/exited state.  Nothing persists; nothing scans the
    whole graph.  The enforcing symbols live in the external =org-glance-llm= plugin
    repo, loaded via =org-glance-plugins=; this invariant is a contract on that
    plugin.  =org-glance-graph:cache-read= / =:cache-write= remain the
    public sidecar API for a plugin that does want a derived, rebuildable cache under
    =cache/= (inv-5 class, dropped by reindex).  Violation: a killed buffer shows
    "running", a restarted one "stopped", or a stored row is trusted for anything live.

24. *Table point restoration restores the CELL — row AND column.*  Every refill captures
    =org-glance-view:point-context= (ID LINE COL) and restores through
    =org-glance-view:restore-point=, which re-lands on the same cell by its
    =table-view-col= key; a row that left the view falls back to its screen line.  Both
    tables obey it — the headline table's =--finish= / =--reload= / bulk-todo paths and
    the LLM sessions table's =g=.  Violation: the cursor drops to column 0, where the
    next =i= (edit cell) or =C-c -= (remove column) acts on the WRONG column.

25. *Links are addressed by their list path; the link's own item label is dropped.*
    =org-glance--link-paths= gives every link a PATH of enclosing plain-list item labels
    plus its own LABEL (=org-glance--link-label=): its description, else the =KEY:= text
    introducing it in its own item (=- Local: [[file:~/x]]= reads "Local"), else the raw
    link.  =org-glance--link-ancestry= drops the innermost item (the label already names
    it), and a link outside any list gets a one-element path, so flat and nested bodies
    share one representation.  =org-glance--pick-link-pos= descends one component per
    prompt, takes a lone candidate at any depth without asking, and offers
    exhausted-path ties by TARGET — without that base case identical paths recurse
    forever.  Violation: every leaf becomes a one-option prompt, or the picker hangs.

26. *Plugins load error-demoted, self-register, and never unload.*  A plugin is
    =org-glance-<name>.el= listed in =org-glance-plugins= and =require=-d by
    =org-glance--load-plugins= (inv 9) before the graph opens; it appends its own
    transient entries at load (remove-then-append, so a reload never duplicates) and
    binds its own keys.  There is no unload protocol: disabling = dropping it from the
    list and restarting.  Violation: a broken third-party plugin bricks
    =org-glance-init=, or reloading duplicates its UI.

27. *Save-hook depth ordering is load-bearing.*  =org-glance-material:sync= runs at depth
    0, =--decrypt-buffer= at 90, =--hide-reserved-properties= at 100, so =sync= reads the
    buffer while it is still SEALED and the WAL, the property index and every projection
    see ciphertext — the mechanism behind inv 14.  Violation: lowering =--decrypt-buffer=
    below =sync= indexes decrypted plaintext into =headlines.jsonl= and the property
    cache.

28. *Multi-block crypt rewrites iterate LAST to FIRST.*  Both
    =org-glance--crypt--transform-blocks= and =--crypt-unwrap-blocks= walk =(reverse
    (block-regions))=: any length-changing rewrite invalidates the recorded positions of
    blocks after it.  Violation: a headline with two or more =#+begin_crypt= blocks is
    corrupted on seal/unseal.

29. *org's =ARCHIVE= marker is never a collection tag.*
    =org-glance-headline--from-element= removes it from the parsed tag set (the
    =archived?= flag carries it).  Violation: a phantom =archive= tag appears in
    =graph:tags=, the capture picker and every per-tag view, over headlines the ambient
    filter hides.

30. *=graph:get-headline= is tri-state: nil / =tombstone= / metadata.*  Read-only callers
    collapse the first two through =org-glance-graph:live-meta=.  Two callers need the
    distinction and share one guard: =org-glance-graph--tombstone-spec= answers the
    record a delete owes or nil, for =org-glance-graph:delete= (which appends it alone)
    and =org-glance-graph:refresh-external= (which carries it into the one batch its
    whole fold appends).  Violation: collapsing tombstone to nil resurrects deleted ids
    in derived indexes and appends duplicate tombstones; spelling the guard twice lets
    the two drift.

31. *=org-glance-material= must never top-level =require= =org-glance-table=.*  The
    dependency runs table → material; the relation pivot
    (=org-glance-material:references=) requires table at CALL time.  Violation: a
    circular load that breaks byte-compilation and init.

32. *Torn-line tolerance is scoped to the open segment's FINAL line.*
    =org-glance-graph--scan-file= swallows a =json-error= only for the last line of the
    open segment and re-signals everywhere else.  Violation: tolerating a torn line
    mid-file silently masks real store corruption.

33. *An external writer announces moved and deleted blobs; READS fold them in.*  The
    =glance= daemon appends =\{"id":…,"at":…\}= lines to =meta/EXTERNAL.jsonl=
    (=O_APPEND=, whole lines) and touches nothing else under =meta=; a DELETE is those
    two fields plus ="tombstone":true=, the only third field and the only value it
    takes, so a line's absence of it IS the write.  =org-glance-graph--read-external=
    keeps ONE entry per id at its first sighting carrying its LAST sighting's kind
    (=--latest-records='' own rule), so a write followed by a delete in one window folds
    as the delete; the kind test is =(eq t …)=, =json-parse-string= mapping JSON false
    and null to the non-nil =:false= and =:null=.  An unknown key is inert both ways: a
    new =glance= against an old org-glance degrades to a skipped ="no stored blob"=, an
    old =glance= writes no third field at all.  Every read folds pending entries through
    =org-glance-graph--fold-external-maybe= (=--ensure-cache=), so an outside edit needs
    no command; the fold is throttled (=org-glance-graph-external-poll-seconds=, one
    =--external-pending-p= per graph per interval — a stat and a cursor read per SOURCE,
    no hash), non-reentrant (=--folding-external=, bound by =refresh-external= itself)
    and =condition-case='d, so it can neither loop nor break a read under
    =debug-on-error=.  The whole batch — records and tombstones alike — is ONE
    =graph:insert=; the fold's cursor moves only AFTER that append (crash rule: a
    repeated write costs an equal record the latest-per-id fold cannot distinguish, a
    repeated delete finds the id tombstoned and appends nothing).  Violation: reversing
    the two steps loses an edit outright; per-id inserts break the one-append rule the
    crash argument rests on; folding inside a fold recurses; an unguarded signal takes a
    plain read down with it.  What this fold gives up is [[*Known hazards][H2]].

34. *The fold moves a CURSOR; it never rewrites =EXTERNAL.jsonl=.*

** The cursor

=meta/EXTERNAL.cursor= is =OFFSET WINDOW PREFIX= — one decimal BYTE offset plus two
=secure-hash 'sha1= digests of the bytes it names, spelled positionally; one plist's
=:offset=, =:window=, =:prefix= in code.  BYTES, the writer appending bytes where Emacs
reads characters and a fold consuming whole lines.  =--set-external-cursor= writes it
temp-then-rename AFTER the records land (inv 33's crash rule); digests come off an
explicitly unibyte =insert-file-contents-literally=.

WINDOW =[max(0, OFFSET - 4096), OFFSET)=, verified by the idle poll, bounded.  PREFIX
=[0, OFFSET)=, verified by every fold that consumes anything, out of the buffer it
holds.  =--external-digests= mints and verifies both, so the two sides cannot drift;
the fold refuses a cursor whose two digests describe different files.

FIVE refusals read as 0: a cursor absent, garbled, carrying fewer than TWO digests,
naming bytes that no longer hash to what it recorded, or naming MORE BYTES THAN THE
FILE HOLDS.  None is guarded with =max=, backwards costing only a re-fold.
Past-the-end is its own test, taken before anything is hashed — =--external-digests=
CLAMPS, so a bogus offset hashes exactly what the size does.  Reproduced: =4096 <same>
<same>= over a 41-byte file read as 4096 bytes folded.

** One read

ONE READ ANSWERS THE WHOLE FOLD.  =--external-bytes= puts the file in a unibyte buffer
ONCE; =--external-folded-in= hashes =[point-min, point-min+OFFSET)= of it to verify the
cursor, the unfolded text is sliced from the same buffer, =--external-tail= mints the
new digests over the whole of it.  They ride =--read-external='s =:marks= as (PATH
OFFSET DIGESTS); =--set-external-cursor= hashes NOTHING.  Offset from one read and
digest from another leaves the FOLD WINDOW between them — every blob read, every org
re-parse, the =graph:insert=.  An APPEND is not caught and must not be: the prefix a
fold measured is stable while it is measured, this file being append-only.  Reproduced
with =git fetch && git reset --hard origin/main= from inside a fold, 3/3; measured at
the 1 MiB cap, 22.3 ms over 2 reads and 2.0 MiB hashed against 26.3 ms over 5 reads and
3.0 MiB.

** The three doors the digest closes

1. A GIT UNION MERGE inserting the other machine's unfolded lines AHEAD of the offset
   while the cursor fast-forwards with no conflict (=--ensure-gitattributes= wrote
   =*.jsonl merge=union= into =meta/=, the cursor TRACKED beside the file): the fold
   resumes MID-LINE, the fragment fails =json-parse-string= and is skipped in silence,
   the line in front of it never seen.  Shut on a store that never tracked the family
   and on no other.
2. The conflict RESOLVER: =--union-resolve-file= is =f-read-text= then =f-write-text=,
   re-laying every byte behind a stripped marker line — shut by structure (inv 8).
3. A rewrite with ONE WRITER — hand edit, restore from backup, botched rotation — which
   no sync rule rules out; each degrades to a re-fold, idempotent by the crash rule.

** A read that failed is not an answer

THE BUFFER IS THE FILE OR FN IS NOT CALLED.  Four shapes signal: absent; unreadable; a
DIRECTORY wearing a generation's name; a DANGLING SYMLINK.  Each caller names its own
refusal — nothing owed for the tail, nothing folded for the offset, NOT FOLDED WHOLE
for rotation; =--external-window= needs none, MEASURING what it read against the range
it asked for.  The two reads refuse in opposite directions: =--external-cursor=
swallows its own =file-error= deliberately (an unreadable cursor costs a re-fold),
=--external-bytes= swallows none (an unreadable file must never read as folded).
Reproduced: under the swallowed read =0 = 0= answered =--external-folded-whole?= =t=
and rotation unlinked a =chmod 000= generation carrying an unfolded tombstone.

** The bound: nothing irreversible happens on bounded evidence

The POLL is bounded (being wrong costs a fold that finds nothing owed); the FOLD is
exact; ROTATION's move is exact (=--external-folded-whole?=).  Two changes the bound
forbids: anything DESTRUCTIVE asking the poll's question, and the fold dropping its
prefix check because the poll "already checked".

ONE QUESTION PER SOURCE PER CYCLE.  =--external-survey= reads each source's cursor once
and asks =--external-drained?= — THREE conditions: the offset is the file's SIZE, the
byte before it is a NEWLINE, the window still hashes.  Only where that bound says bytes
MAY be owed does it read the file whole through =--external-tail=.  The poll
(=--external-pending-p=) and the fold (=--read-external=, =--rotate-external-maybe=)
read that one survey.  =--fold-external-maybe= runs before EVERY graph read at a 1 s
throttle; two generations at the cap is the steady state.  Measured per poll with
nothing owed, size alone / whole prefix / window + prefix: 4 KiB 0.28/0.49/0.43 ms,
1 MiB 0.28/8.50/0.64, 4 × 1 MiB 0.74/36.10/1.61.

A SIZE COMPARISON IS NEITHER SOUND NOR NECESSARY: =Data.Org.External.noteLine= spells
FIXED-WIDTH lines, so a same-size whole-file replacement is this file's TYPICAL
re-laying (hand edit, restore, botched rotation, union merge on a store that tracked
the family), and the same unverified predicate guarded rotation's DELETE loop.
Reproduced: a 58-byte file replaced by a 58-byte tombstone for another id stayed unread
over twenty polls.  THE WINDOW IS SOUND FOR THE EVENTS THAT HAPPEN: an insertion or a
deletion ahead of the offset shifts every byte after it, this window included; a
replacement is caught whenever it touches the last 4 KiB.  THE WIDTH IS CONSTRAINED
UPWARD AND FREE DOWNWARD: widening it to the whole prefix reddens
=external-the-fold-catches-what-the-window-passed= and
=external-rotation-spares-a-generation-re-laid-mid-fold=, narrowing to 512 leaves all 50
cases green at the cost of promptness.

THE RESIDUAL: a same-LENGTH edit further back than the window passes the poll.  The
FOLD verifies the whole prefix, so on a file somebody APPENDS TO it lasts until the
first byte owed (glance's =scan= reports the interval as index disagreement meanwhile);
NOTHING EVER APPENDS TO A ROTATED GENERATION, so there it lasts as long as the file.
Reproduced at cap 6000: a drained 6960 B generation re-laid from inside =graph:insert=
(same size, last 4 KiB identical) was called drained and unlinked, its tombstoned id
still LIVE twenty folds later.  THE ANSWER MUST ALSO BE FRESH: rotation reads the
candidate itself, the =:marks= in hand having been taken before it, the fold window
between being where a checkout or a merge re-lays bytes.

THE NEWLINE ASSERTION IS FREE TO BE WRONG IN ONE DIRECTION: the POLL asserts it, the
FOLD does not — asserted on the fold path it would re-fold the whole file forever,
appending equal records on every read.  Its one false refusal is a final line the WRITER
tore, leaving the cursor mid-line; that store polls pending and folds nothing until the
next append restores a boundary.  A TORN LINE THAT RIDES INTO A ROTATION NEVER GETS
THAT BOUNDARY BACK: that generation reads pending for as long as it exists, one fold per
poll interval taking nothing — pure cost and no loss, every byte HAVING been folded;
it ends at the next rotation, whose =--external-folded-whole?= makes no newline
assertion.

** The hash budget

FOUR PER SOURCE THE SURVEY READ WHOLE — two ranges, minted and verified — and nothing
else hashes.  Bytes owed: FOUR (=--external-folded-in= verifies the claimed window and
prefix, =--external-tail= records both, out of one buffer; a cursor absent or garbled
hashes NOTHING).  Read whole with nothing owed: TWO (the tail verifies, no cursor
written).  Blessed by the bound: ONE, over at most =--external-window-bytes=, no whole
read — the poll's own cost, which the fold pays exactly.  A pass that ROTATES: ONE per
candidate generation the survey did not read, NOT bounded (=--external-folded-whole?=
over the whole prefix, ~9 ms at the cap).  A candidate the pass DID read whole carries
that verdict in the survey and is not asked again; WHAT THE SKIP GIVES UP is the
residual above and nothing more, ROTATION carrying the repair (=--external-refold=).

The fold is O(BYTES OWED), flat in settled generations: over 5 drained 1 MiB
generations 48.5 → 5.5 ms and 5,263,573 → 20,663 B hashed, the rotating pass 4,210,779
→ 2,113,615 B and 126.4 → 71.0 ms.  THE FIRST-SIGHTING SET IS A HASH TABLE, keyed by
hash with the ORDER in a list beside it and materialized at the end, so first sighting
still decides position and last sighting still decides kind; =(assoc id entries)= over
a list is quadratic in a source's distinct ids, ~18,000 at the 1 MiB cap (5,029.6 ms
against 72.7 ms).

** Rotation and retirement

GROWTH IS ROTATION (=--rotate-external-maybe=): the file is renamed, never truncated,
and it FIRES ON THE OFFSET THE FOLD TOOK.  =refresh-external= hands rotation its own
SURVEY; the live file's entry is both conditions at once (=--external-took=) — there
because bytes were folded, its OFFSET the size that fold read and has just written the
cursor to, drained by definition.  A SIZE re-stated afterwards makes the cap bound
nothing (reproduced at cap 32768: 12 folds, 99,456 B, ZERO rotations).  Bytes past that
offset ride into the generation and are folded there, a generation being drained ahead
of the live file.

Cursor renamed to =EXTERNAL-<gen>.cursor= and file to =EXTERNAL-<gen>.jsonl=, CURSOR
FIRST: a generation with no cursor is re-folded whole (a no-op) where a fresh live file
under the old cursor would have its first lines skipped.  The daemon recreates the live
file on its next append, opening the path per line (=Data.Org.External.appendLine=,
=O_CREAT|O_APPEND=), so a rename between its open and its write lands that line in the
ROTATED file — which still exists, is drained ahead of the live one, and is NEVER
retired on the pass that made it, an older DRAINED generation going at the START of the
next rotation.

ROTATION MOVES A SPENT GENERATION; IT NEVER UNLINKS ONE.  =--external-retire= renames it
into =meta/spent/=, cursor first and file after; NO CODE PATH EVER REMOVES WHAT IT LEFT.
The destination is beside the files it holds, so the rename is ONE atomic operation (a
cross-filesystem =rename-file= degrades to a copy and a delete); =meta/= is already off
every org walk (glance's denylist names it whole); =directory-files= over =meta/= with
=--external-generation-re= names neither that directory nor its contents, taking a
retired generation out of =--external-sources= with no filter to forget; and a store
moved by path takes its spent generations with it.

A RETIRED GENERATION IS OUT OF THE FOLD'S REACH.  THE REPAIR IS BY HAND, one =mv=: the
=.jsonl= ALONE back into =meta/=, where it carries no cursor and the next fold takes it
WHOLE, idempotent by the crash rule; moving the cursor back would restore the answer
that was wrong.  THAT REPAIR STRANDS THE OLD CURSOR under =spent/=, so the next
retirement finds its destination taken, =--external-move= refuses to clobber, and the
fresh =EXTERNAL-<gen>.cursor= is left in =meta/= for good — inert, nothing reading a
cursor whose =.jsonl= is gone, rotation minting strictly above the newest generation
=meta/= holds (=butlast= sparing it) so no number comes round again.  Pinned by
=external-retire-refuses-a-destination-that-exists=.  NOTHING PRUNES =spent/=, taken
deliberately: =org-glance-graph:clear-spent-external= is the explicit door,
=rm -r <store>/.org-glance/meta/spent/= the other, and both are the reader's.

A GENERATION IS RETIRED ON ITS OWN CURSOR AND NOT ON ITS POSITION.  Each candidate
=butlast= names is asked =--external-folded-whole?=: whole prefix hashed out of one
read, size and verified offset out of that same buffer — unless the survey already read
it whole, whose verdict is the same reading, and it is not hashed twice.  A candidate
the check REFUSES stays where it is AND HAS ITS CURSOR DROPPED (=--external-refold=);
the next fold takes it whole, a no-op where the bytes did not move and the repair where
they did.  A generation not folded whole STAYS however old it is, and so does a
DIRECTORY or a DANGLING SYMLINK wearing a generation's name.  ABSENCE OF EVIDENCE NEVER
LICENSES A MOVE: a generation that appeared after =--read-external= listed the sources
carries no cursor and is spared, with no rule of its own.  Position decides only which
generations are CANDIDATES, the newest spared whatever its cursor says (an in-flight
open is about to land in it).  So "at most two on disk" is "at most two FOLDED-WHOLE
ones IN THE LIVE DIRECTORY".

** The git ignore

=--ensure-gitignore= keeps four things out of git — the live =meta/EXTERNAL.jsonl=,
every rotated generation, every =.cursor= beside one, the =meta/spent/= directory — as
two globs and a directory, beside the =cache/= line already there.  The family is a
LOCAL HINT between the LOCAL daemon and the LOCAL Emacs; what crosses machines is the
WAL RECORD the fold produces.  ON A STORE THAT NEVER TRACKED THE FAMILY it removes the
union-merge door and the resolver's reach into this family (belt beside inv 8's braces);
THE DIGEST STAYS, load-bearing on a store the ignore came too late for.

THE RETROFIT IS AN APPEND, where every other bootstrap marker is write-if-absent:
=--ensure-gitignore= adds each line the file LACKS and leaves order, comments and
hand-written rules alone.  Two costs, both taken: a line removed by hand comes back at
the next open, and IGNORING DOES NOT UNTRACK — a store that already committed these
files needs =git rm --cached .org-glance/meta/EXTERNAL*= (and =meta/spent=) run by hand
once, and =git add -f= keeps one tracked on purpose.  MEASURED WITH REAL GIT: over a
store whose family is tracked the four patterns leave =git check-ignore -q= exiting 1,
=git status= reporting =EXTERNAL.jsonl= modified after an append, and the next commit
carrying its bytes.  NOTHING IN THE SUITE ASSERTS THAT HALF:
=org-glance-test:git-ignores= runs =check-ignore= over a repository holding nothing,
where the patterns ARE the whole answer — said in the helper's own docstring.

NOT TAKEN: A NOTIFICATION FILE PER MACHINE, =EXTERNAL-<host>.jsonl=, one writer each and
one cursor per reader; it would buy H3 back and shut the merge on the stores the ignore
cannot reach.  Three obstacles: the line format is a FROZEN cross-repo contract and the
file NAME is part of it, so the daemon must learn a host and both sides agree how one is
spelled (=system-name= against a container's hostname is no stable key); the reader
folds N files where it folds one, and =--external-sources='s ordering rule — generations
before the live file — has no meaning ACROSS hosts, so last-sighting-wins would need a
rule about whose sighting is later, a clock comparison this design has deliberately
never made (=at= is recorded, nothing acts on it); and the digest is owed anyway, a hand
edit, a botched rotation and a restore all being single-writer events.

** Violation

- Rewriting the file at all reopens the race H1 names: a fold dropping what another
  already took eats the head of whatever arrived between, and a lost tombstone never
  self-heals, the blob being gone.
- Trusting an offset whose digest no longer holds resumes mid-line and skips lines
  nothing read.
- Hashing at WRITE time, or verifying against a SECOND read, leaves that door open for
  the whole fold window and closes it nowhere else.
- Asking the poll for a SIZE leaves a same-length re-laying unfolded forever; asking it
  for the whole prefix puts a SHA-1 of every folded byte on every graph read; taking the
  prefix check off the FOLD to pay for it puts the residual back with nothing to close
  it.
- ASKING THE POLL'S BOUNDED QUESTION ANYWHERE DESTRUCTIVE loses a generation outright —
  on a file nothing appends to, that residual never expires.
- Rotating on a size re-stated after the fold makes the cap bound nothing.
- Retiring a generation on the pass that rotated it loses the line an in-flight open is
  about to write; retiring one by POSITION takes every line it still owed out of reach;
  retiring one on evidence taken BEFORE the fold ran takes one the fold window re-laid.
- UNLINKING INSTEAD OF MOVING makes every one of those a loss where a move makes them a
  recoverable misfiling — what six of the seven closed holes had in common.
- Reading a FAILED READ as an answer says the file is folded whole and takes it away
  unread.
- Un-ignoring the family puts the merge door back.

REJECTED: a lock across Emacsen (inv 7; there is no mutation to serialise), and
shortening the file under any guard, =f-write-text= being =write-region= with =append=
nil and destroying whatever the daemon appended between its own read and its own write.

* Known hazards

Costs the code ships WITH, deliberately.  Each was reproduced with a probe and each
earns a test in [[file:../test/test-external.el][test-external.el]] pinning today's
behaviour, so closing one turns its own case red.  An OPEN entry states what it costs,
what would close it, why it stands; a letter is never reused, and a CLOSED entry keeps
its place so the symptom stays findable.

** H1 -- CLOSED 2026-08-12: the external fold's truncate race ate a tombstone

*The symptom.*  =org-glance-graph--truncate-external= rewrote the file with a character
COUNT dropped from its head, counted against the file the fold had read; inv 7 gives two
Emacsen folding one store no lock, so the second truncate ate the head of whatever
landed between.  Reproduced: E2 reads 74 characters, E1 folds and empties, the writer
appends the 91-character tombstone, E2 truncates by 74 and leaves =tombstone":true}= —
the record LIVE, the fragment surviving every later fold.  A lost write note self-heals,
the blob still being the truth; a lost TOMBSTONE never does, the blob having gone.  A
compare-and-swap on the prefix did not close it, leaving an inner window: =f-write-text=
is =write-region= with =append= nil, so a line the daemon appends between that
function's own =f-read-text= and its own =f-write-text= is destroyed — the same symptom,
reachable with ONE Emacs.

*Closed by inv 34*, which removes the mutation: the fold reads from a byte cursor and
writes that cursor forward, growth handled by rotation.  Pinned by
=external-race-spares-the-tombstone=, =external-keeps-a-note-that-arrived-mid-fold=,
=external-keeps-a-byte-identical-note=, =external-double-fold-is-a-no-op=,
=external-a-cursor-that-says-nothing-refolds= and the four rotation cases.

*What the cursor cost, and what pays it.*  Anything re-laying the bytes ahead of an
offset resumes the fold MID-LINE, the fragment skipped in silence and the line in front
of it never read — H1's own symptom under a new cause, reproduced with the real fold.
Its four doors are inv 34's three plus the merge, shut only where git does not already
track the family (inv 34, at the cost of H3), an ignore reaching no tracked path.  The
PREFIX DIGEST answers all four by giving the position an identity: a prefix that moved
re-folds.  The residual goes with it — under the swap a note arriving byte-identical to
the text a fold read was dropped with it, where an OFFSET counts bytes rather than
comparing them (=external-keeps-a-byte-identical-note=).

** H2 -- a folded delete is undone by the id's open material buffer

=org-glance-material:delete= discards the id's open material buffer, naming unsaved edits
in its consent prompt (inv 11).  The fold's tombstone arm inserts the spec and touches no
buffer, so that buffer survives a folded delete and the next save's
=org-glance-material:sync= appends a LIVE record over the tombstone.  Reproduced
(=external-delete-is-undone-by-an-open-buffer=), both ways: with the blob directory left
standing the save is silent; with it removed — as the daemon leaves it — the save asks
org's own "Directory does not exist; create?" and a =yes= puts the blob back too.  A =no=
aborts the save, so =after-save-hook= never runs and the tombstone stands: the record and
the blob never come back apart.  What does not come back is the blob's occurrence
history, canonical content under inv 5.

- *Costs:* one live record and one recreated blob per delete of an id somebody had open,
  minus that id's =occurrences/=.  Record and document come back together, so no
  store-level counter moves in the ordinary interleaving.  It IS visible in one: a save
  landing BEFORE the fold reads leaves the tombstone standing over a blob back on disk,
  which =glance='s scan counts as an unindexed blob (=Data.Org.Index.driftOf=,
  =dfUnindexed=) — pinned as =external-delete-after-a-save-strands-the-blob=.  Deleting
  the resurrected id through =glance= again is refused, its trash destination already
  holding that id (=Data.Org.Trash=, "the trash already holds"); =M-x org-glance-delete=
  clears the record.
- *Would close it:* discarding the buffer in the tombstone arm, as =material:delete=
  does; or discarding only CLEAN buffers and leaving a dirty one with a warning.
- *Open because:* a fold runs in the BACKGROUND, off any read, and =material:delete='s
  consent-when-dirty guard exists precisely because discarding a dirty buffer needs a
  human.  Silently discarding one during a background fold breaks inv 11 to save a record
  =M-x org-glance-delete= clears in one command.

** H3 -- a daemon HERE cannot notify an Emacs THERE

The notification family is git-ignored (inv 34): =meta/EXTERNAL.jsonl=, every rotated
generation, every =.cursor= and =meta/spent/= stay on the machine that wrote them, so the
DAEMON-HERE / EMACS-THERE topology stops working — machine B folds nothing machine A's
daemon announced.

- *Costs:* nothing where the daemon and Emacs share a machine, which is what =glance= is
  built for — it serves 127.0.0.1 and writes the blobs Emacs reads.  Where they do not,
  B's records go stale until somebody runs =M-x org-glance-reindex= there, or A's Emacs
  folds and syncs the WAL records that fold produced.  Deleted ids are the sharp end: a
  tombstone A folded does reach B through the WAL, but a delete NOBODY folded reaches
  nobody.
- *Would close it:* a notification file per machine, =EXTERNAL-<host>.jsonl=, one writer
  each and one cursor per reader per file — then the family can sync and no merge can
  corrupt it.  Written up under inv 34's NOT TAKEN, with the three things standing in its
  way.
- *Open because:* what syncing bought was one hazard-carrying door — the git union merge
  that inserted another machine's unfolded lines ahead of a live cursor and cost a
  tombstone (inv 34, H1's second cause) — for a topology nothing in either repo supports
  today.  A reader who has it can undo the decision per store: the ignore does not
  untrack, so =git add -f= over the family keeps it synced, and the merge door comes back
  with it.
