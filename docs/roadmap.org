** DONE Export one verified authority path set for portable checkpoints
The shared cache now exports sorted graph-relative paths from its current
production inventory and refuses stale inventory, unverified families,
symlinks, cache state and paths outside the graph. This supplies the missing
source boundary for Glance's portable checkpoint admission contract.

** DONE Seal and hydrate portable projection checkpoints
Explicit sealing writes one gzip-compressed logical projection and one
proof-bound descriptor at immutable content-addressed paths. Cold open hydrates
an exact compatible artifact before asynchronous reconciliation; an append-only
family tail hydrates the base and replays the tail. Corruption, configuration
drift, ambiguity and publication failure refuse the artifact without replacing
the live cache. Normal edits write no tracked checkpoint state.

** DONE Keep transient read entrypoints on the committed cache
Materialize, Open link and Overview no longer cross the WAL census or cache
writer boundary. Exact and list reads use transaction-free SQLite readers while
reconciliation runs in the background. On the 6,780-Row reference projection,
their p50 model-read times are 513.9, 269.9 and 96.3 ms respectively, with
zero full censuses and zero maintenance transactions. Opening a selected
Material Row now uses indexed relation and exact Row reads, reducing its p50
from 16,684.6 ms to 66.0 ms.

Material opening now resolves and digest-checks its current Snapshot entirely
from the committed projection. Tag-filtered Overview preselects candidates in
SQLite; at 2,000 Rows its p50 fell from 201.2 ms to 9.5 ms. The action benchmark
asserts zero reconciliation requests, full censuses, cache maintenance
transactions, and History reads for every transient read entrypoint.

The full tagged Table entrypoint now includes saved property columns in that
contract. Its state palette and hash-current property cells reuse the selected
committed Rows and property sidecar. On the 448-Row =alberblanc= view, isolated
rendering fell from more than 30 seconds to 0.367 seconds. A live Emacs whose
loaded package directory was replaced also discovers the newest installed
package for its worker, and an exit-255 failure names the retained process
buffer. org-glance 1.55.0.0.20261012.16 carries the fix.

** DONE Publish full recovery as a separate committed generation
Full recovery clones the shared cache, replaces only org-glance-owned state,
replays every authoritative family, validates integrity, foreign keys, format,
and readable projections, then atomically publishes the staged database. A
failed build leaves the prior generation readable. Glance-owned Rows and their
incoming edges survive the org-glance replay. Routine workers keep the existing
generation and use incremental proof reconciliation; a missing cache selects
staged recovery. A concurrent local event invalidates the staged inventory and
forces retry without replacing its newly committed Row. Fourteen
alternating-order samples over the 257-family fixed
fixture measure 1,535.5 ms p50 and 1,663.8 ms p95 versus 1,531.7/1,621.2 ms
for in-place replay; generation publication itself is 0.055 ms p50.

The 2026-10-16 coordinated repair extends staging to bulk refresh and
reconciliation. Publication now copies validated state through one WAL
transaction and retains the live database inode. A retained-connection
=data_version= check rejects stale work; source proofs are rechecked before
publication. Checkpoint hydration overlays org-glance-owned rows onto a clone
of the current live generation, preserving current Glance rows and metadata.
Passive reads also tolerate the unpublished first schema. Full validation:
533 task-only package tests, 534 with the pre-existing user regression, and
39 Glance interop cases. A 1,000-family build spends 42.1 ms in live publication
out of 12,603.5 ms total. See
[[file:proposals/2026-10-16-passive-cache-publication.done.org][passive cache publication]].

The S16 follow-up repairs missing family projections independently of
directory-proof freshness. Coherent stale inventories retain incremental
reconciliation; unchanged warm startup creates no stage. Final validation
passes 535 task-only ERT cases and 536 with the existing user regression.

** DONE Reconcile clean Git event transitions incrementally
The existing-cache batch worker compares the accepted and current clean commits,
maps changed immutable paths to logical family IDs, and folds only those
families. Dirty, incompatible, or unclassifiable transitions retain the complete
census; missing caches retain staged full recovery. On a 1,000-family fixture
with one changed family, completion falls from 3,062.6 to 663.5 ms p50 and
maximum foreground probe latency from 142.9 to 81.7 ms.

** DONE Remove read-path reconciliation and cooperative recovery
Compatibility-WAL reads no longer survey the external relay, fold it, or queue
cache work. A bounded one-second coordinator poll wakes the isolated worker,
which drains the relay; explicit relay refresh remains available. Recovery runs
only in that worker and contains no =thread-yield= policy branch. Focused
regressions and the interop gate prove prompt delivery without read maintenance.

** DONE Observe each immutable family once
The version owner now returns one observation containing the published
inventory, History, and already-read payload bytes. Cache integrity, parsing,
projection, and recovery reuse those bytes. Ordinary versioned graph writes
share the same observation and refresh it only after legacy migration mutates
the family. Focused counters require one census and one payload read per
Snapshot during projection, and one census for a versioned graph write. The
ten-Snapshot benchmark retains its fingerprint and exact one-census work count.

** DONE Publish graph changes to incremental consumers
Graph commits now publish bounded Row IDs or structural invalidation through
error-isolated graph listeners. Open views subscribe once; unfiltered Overview
refreshes splice safe single-Row changes and fall back to full rendering for
structure, filters, missing Rows, or incoming relation labels. At 1,000 Rows,
the paired benchmark measured 27.6 ms for a full refresh and 2.1 ms for a
one-Row refresh.
