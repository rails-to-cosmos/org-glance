Thin [[https://orgmode.org/][org-mode]] metadata layer, query engine and UI for [[https://www.gnu.org/savannah-checkouts/gnu/emacs/emacs.html][Emacs]].

* Install

#+begin_src emacs-lisp
(add-to-list 'package-archives '("rails-to-cosmos" . "https://rails-to-cosmos.github.io/elpa/"))

(use-package org-glance
  :bind (("C-x j" . org-glance-transient))
  :config (org-glance-init)
  :ensure t)
#+end_src

The =rails-to-cosmos= archive provides =org-glance= and its [[https://github.com/rails-to-cosmos/table-view][table-view]] dependency; the remaining deps (=dash=, =f=, =s=, =aes=, =transient=) come from MELPA, so keep a MELPA entry in =package-archives= too.

* Usage

Entrypoint is =org-glance-transient= (=C-x j=).

** Capture

=C-x j += → pick (or type) a tag → an org-capture-style buffer opens →
write an ordinary headline, =C-c C-c=:

#+begin_src org
,* TODO [#A] Kopi Luwak :coffee:
  SCHEDULED: <2026-08-01 Sat> DEADLINE: <2026-08-10 Mon>

  Passed through a civet.
  [[https://example.com][Homepage]]
#+end_src

** Overview

=C-x j o= → pick a tag → its *table*: one row per headline, colour-coded todo states:

#+begin_example
| State | Title      | Scheduled        | Deadline         | Pri | Tags   |
|-------+------------+------------------+------------------+-----+--------|
| TODO  | Kopi Luwak | <2026-08-01 Sat> | <2026-08-10 Mon> | A   | coffee |
#+end_example

Overview and table views show each current headline once, even when the cache
retains older snapshots. Separate headline IDs and unresolved conflict versions
remain separate rows.

=O= toggles to the org-text *overview* — a plain read-only org buffer, so folding, =C-x j a= (agenda) and link clicking all behave exactly as in org. Each overview heading is self-sufficient:

#+begin_src org
,* TODO [#A] Kopi Luwak :coffee:
DEADLINE: <2026-08-10 Mon> SCHEDULED: <2026-08-01 Sat>
- [[https://example.com][Homepage]]
#+end_src

Act on the row/heading at point without opening anything:

Column layout, sort and added columns persist per tag.  Optionally give a tag
its own config: todo cycle and capture template (=C= in the transient — or =C=
in that tag's overview / table to edit it directly). =config/system.org= supplies
a graph-wide TODO cycle; tag cycles appear as additional =#+TODO:= lines. Each
overview line carries preceding comments naming its source config files.

** Edit a headline

=RET= on a row/heading (or =C-x j m= anywhere) opens the headline's logical
Org editor. Reopening the headline returns the same buffer and preserves its
draft. =C-x C-s= publishes an immutable child and advances the editor's base
while retaining text, location, folding and undo. =C-x s= includes these editors.
Closing a dirty editor offers save, discard or cancel; normal Emacs exit
requires consent before discarding any remaining drafts.
Pending publication counts as unsaved work even when undo restores the
unmodified flag; save, save-all, close and exit retain recovery protection.

Material buffers have no visited file. Backups, lockfiles and automatic disk
saves are disabled, including Org source edit buffers. Completed saves have
immutable history; unsaved drafts are lost after process failure. Save or
discard existing file-visiting material buffers and restart Emacs when upgrading.

Bookkeeping properties such as =:ORG_GLANCE_ID:= stay outside the editing text;
the serializer supplies them on every publication. Revert loads the current
verified snapshot after consent to discard a dirty draft. A newer external
snapshot refreshes a clean editor at a display boundary; changed frontiers,
deletions and damaged payloads preserve dirty drafts and refuse unsafe saves.
Revert refreshes the frontier and conflict state when the snapshot is unchanged.

=org-glance-material:export= writes an ordinary content copy while retaining
the editor. =diff-buffer-with-file= compares ordinary content with a pinned
base preview. These commands refuse crypt content. Exact-version rows open
read-only previews; =C-c C-c= there restores that version into the logical
editor for a subsequent save with the captured current parents.

Org source editing works through its parent editor. Indirect buffers support
shared text edits and saves; Material commands use the logical editor. Relative
file links resolve from the graph directory. Graph configuration supplies TODO
and tag context; snapshot file-local and directory-local variables are skipped.
Capture retains its separate temporary-file workflow. File-based refile targets,
file capture targets, VC commands and other consumers requiring a visited file
need an exported file or their own domain integration.

=org-glance-capture= stamps =ORG_GLANCE_CREATION_TIME= when the capture is
finalized. The stamp stays in the stored =data.org= and is hidden in the
material buffer with the other managed properties.

** Relations

In a materialized buffer — or while capturing (step 1) — =@= at the start of a word prompts for another headline and inserts a =glance:= link to it; an active region becomes the link title. =C-u @= asks for the reference *kind* first, then the headline. Older =org-glance-material:= and =org-glance-visit:= links still resolve as deprecated aliases:

#+begin_src org
roasted by [[glance:0e904834?kind=roasted-by][Manhattan Coffee Roasters]]
#+end_src

Clicking the link opens the roaster; the graph indexes it as a typed edge, and the views pick it up. The overview heading gains a relation line:

#+begin_src org
- roasted by [[glance:0e904834][Manhattan Coffee Roasters]]
#+end_src

Descriptive references display the target's current state and title, such as
=DONE Buy tickets=. The saved link description stays intact for editing and
export. Targets without a state show their title alone; missing targets keep
their saved label. Graph commits invalidate displayed labels for refontification.

and =C-c += in the table now offers a =Roasted by= column with the target titles:

#+begin_example
State  Title       ...  Roasted by
TODO   Kopi Luwak  ...  Manhattan Coffee Roasters
#+end_example

In a materialized buffer:

| Key   | Action                                         |
|-------+------------------------------------------------|
| =@=     | insert a reference (completion, at word start) |
| =C-u @= | same, plus a reference kind (=roasted by=, …)    |
| =C-c @= | table of everything this headline relates to   |

The =LOGBOOK= also contains editable relation entries. Plain links use =Refers to=
and =Referred by=; typed links capitalize the kind, such as =Blocked by
[[glance:abc][TODO Other headline]] at [2026-01-01 Thu 12:00]=.  The timestamp is
the source snapshot's creation time when the entry was added. Open and revert
append missing entries while preserving existing descriptions and timestamps.
New entries mark the buffer modified. Edit, undo and save them as ordinary Org
text; saving retains the drawer. Logbook links remain bookkeeping; body links
define the graph's relations.

A relation table lists both directions in one view — the headlines this one refers to AND the ones referring to it — and its =Relation= column names each row's direction and kind (=> roasted by=, =<=).  =@= on a row in the table or the overview opens the same view for that headline.

Relation tables open with the default layout; edits to it are not saved automatically (an echo-area nudge reminds you) — =C-c C-c= applies the layout (columns, order, sort) to a scope of your choice: this headline, or a tag pair (=coffee → roaster=, the anchor's tag first).  Every later relation table matching the scope restores it.

A link can also address a whole view: =[[org-glance-overview:coffee?done=nil][Active coffees]]=.

** Encryption

Wrap a region in a crypt block with =C-c #= (no region: the whole body):

#+begin_src org
,#+begin_crypt
bank: 1234-5678
,#+end_crypt
#+end_src

On disk it is ciphertext, and a materialized headline opens THAT WAY -- no password prompt until you ask for one.  Unseal with =C-c #= in the buffer, or materialize with the transient's =-d= switch to open decrypted; saves seal scratch content while the editor keeps its decrypted presentation.  Text OUTSIDE the blocks stays public and searchable.

=C-c #= is the only crypt key; what it does depends on where point is:

| Point / buffer state         | =C-c #=                                   |
|------------------------------+-----------------------------------------|
| active region                | wrap it in a crypt block                |
| sealed buffer (ciphertext)   | unseal it (prompts, hardens the buffer) |
| inside a plaintext block     | unwrap that block -- public on save     |
| decrypted, outside any block | seal it back, forgetting the password   |
| plaintext headline           | encrypt the whole body as one block     |

** Extracting properties

=e= in a table or overview, =C-c e= in a material buffer, and
=M-x org-glance-extract= copy a body =KEY: value= property.  Ordinary and
encrypted properties use the same confidential clipboard path.  Sealed
content prompts for its password before the property picker opens; extraction
decrypts a scratch copy and preserves the live buffer and stored content.

Extraction bypasses the kill ring and message log, and reports success only
after the helper acknowledges publication.  The lease defaults to 15 seconds;
=org-glance-clipboard-ttl= accepts positive integers.  Helpers enforce their
deadlines independently of Emacs.  Linux cleanup retires its own source;
macOS uses ownership-conditional writes to preserve replacements.

- Linux requires Python 3 and permission to lock the source payload buffer.
  Helpers allocate that buffer anonymously, disable core dumps, and refuse
  payload-file storage fallback.
- Wayland requires =ext-data-control-v1= or =wlr-data-control= support from the
  compositor; unsupported compositors refuse copying.  The helper serves
  transfer pipes directly and advertises =x-kde-passwordManagerHint=.
- Graphical X11 requires =libX11=, =libX11-xcb= and =libxcb=; a separate process
  owns CLIPBOARD and leaves PRIMARY alone.  Payloads travel directly from locked
  memory through XCB's raw socket API.  Xlib handles control messages and never
  receives the payload.  Linux helpers reject reads after their sleep-inclusive
  deadline.
- macOS uses two system JXA processes: a publisher and a cleanup guardian.
  Confidential/transient markers and =currentHostOnly= discourage history and
  prevent Handoff sharing.  Either process cleans up if its counterpart exits.
  Cleanup checks the lease token and generation, then replaces only the text
  with an empty string using AppKit's ownership-conditional write.  AppKit
  refuses that write if ownership changes; the nonsecret lease metadata remains.

Use =M-x org-glance-clipboard:paste=, or =C-c y= in a material buffer, to paste
without importing text into the kill ring.  Ordinary =C-y= can import the
clipboard into the kill ring and retain it after expiry; history packages may
persist that copy.  Destination buffer contents, undo, and save policies apply
to both paste commands.

Clipboard managers must honor confidentiality hints.  Copies already delivered
to applications or the macOS pasteboard server cannot be recalled reliably;
stopping both macOS helpers can delay cleanup.  The shared clipboard does not
authenticate what a destination receives.  A destination-specific transfer
avoids that substitution boundary.  Host swap and hibernation policy still
govern plaintext in Emacs and other applications.  Password-cache expiry and
=org-glance-material:lock= leave decrypted material text visible.

** Repeating headlines

A headline with a repeater (=SCHEDULED: <… +1d>=) stays ONE headline.  With =org-glance-repeat-history-depth= set (N newest, =t= = all, per-headline =:ORG_GLANCE_REPEAT_HISTORY_DEPTH:= wins), each completion snapshots the done state before org resets it; the table's =Rep= column marks repeaters, and =l= (=C-c h= in the buffer) opens any past occurrence read-only.

Example — org-text views, everything visible, daily history for a year:

(setq org-glance-overview-default-view 'org-glance-overview
      org-glance-filter-spec nil               ; show DONE too
      org-glance-repeat-history-depth 365)
#+end_src

* Plugins

Optional features ship as SEPARATE packages.  Your package manager installs the
package; org-glance enables it.  Install it, then list it in
=org-glance-plugins= — or press =I= in the transient (=U= disables).  Eagerly
load and initialize org-glance to load enabled plugins at Emacs startup.  The
transient's *System* heading lists what is enabled and marks any plugin whose
library failed to load:

#+begin_src emacs-lisp
(use-package org-glance
  :demand t
  :ensure org-glance-llm
  :custom (org-glance-plugins '(llm))
  :config (org-glance-init))
#+end_src

- [[https://github.com/rails-to-cosmos/org-glance-llm][*org-glance-llm*]] — LLM sessions per headline.  =l= opens an
  [[https://github.com/rails-to-cosmos/agnostic-llm][agnostic-llm]] session in the
  headline's data directory (or its =:ORG_GLANCE_PROJECT_DIR:=, set with
  =C-c d= in a materialized buffer and stored with =~= for home paths and no
  trailing slash); =L= lists every session (running /
  exited / stopped), derived live at each refresh; =C-c l= opens the session for
  the headline at hand.  It depends on =agnostic-llm= (also on the
  =rails-to-cosmos= archive), which pulls in =vterm= — loaded lazily on
  first use.  Core org-glance does NOT depend on it.

* Shared JSON table layouts

When =.org-glance/config.json= is present, tables read and write
=clients.orgGlance.tableColumns=, =tableViews= and =tableRefs=. The existing
column commands and =C-c C-c= use these collections automatically.
=tableColumns= maps tag scopes to custom ={property, header}= columns and a
=hidden= array of built-in column keys. =tableViews= maps filter identities to
ordered column keys and sort records with =column=, =direction= (=asc=/=desc=),
and =nulls= (=first=/=last=). =tableRefs= retains scoped columns, hidden keys,
order, sort and an =applied= timestamp. Title stays mandatory.

Each table pins the revision it opened. If another client saves settings, a
stale layout save reports a conflict and retains the visible draft. Reopen the
table to observe peer settings before applying a fresh edit. Explicit apply
reports busy writers. Automatic saves retain their previous save baseline on
failure and can retry. Unknown settings and peer-client fields survive writes.
Nested extensions follow surviving property/column identities through edits and
reordering. Duplicate identities are refused, and unchanged records retain
exact bytes. Reference layouts still save only through explicit =C-c C-c= with
a chosen scope.

Trees without the shared JSON file retain legacy ELD layout storage during the
coordinated migration. JSON activation prevents an already-open legacy table
from writing a stale ELD layout. This implementation prepares persistence; it
does not import or remove existing ELD files.


* Shared JSON Settings tables

For a tree with =.org-glance/config.json=, =M-x org-glance-settings= opens system
Settings. The existing tag configuration command (=C= in the transient) opens
the selected tag's Settings. Title and Storage edit through ordinary minibuffer
input; Storage requires a listed choice. TODO cycles and Capture template open
child tables. =+= and the final producer row add a cycle or line, =d= removes
an item, and the Order cell moves it. Cycle cells retain keyword metadata;
template Text and Ending cells preserve literal LF, CRLF, CR and final missing
endings. Adding after an unterminated final line supplies a separator using
the existing line-ending convention. Only the final line may have no ending.

=R= removes the selected override; an empty child table remains an explicit
empty override. =C-c C-c= or =C-x C-s= saves all fields in the scope through one
shared JSON transaction. The six columns are Setting, Value, Area, Applies to,
Source and State. Child Back restores the parent's filter, flags, layout and
row/cell point. =q=, Escape and DEL return from a child; closing the root asks
before discarding an unsaved draft. Reopening the same scope retains its draft. System scope and the tag named
=system= use distinct buffers; existing-buffer reuse verifies the scope and
canonical tree identity.

Writes use the observed file revision and preserve peer scopes/clients. A
stale save keeps the draft. =g= rereads and retains nonoverlapping edits;
overlapping fields require an explicit =current= or =draft= choice. Cancelling
that choice keeps the whole prior draft. Save explicitly after reconciliation.
A failed live application retains the saved revision for retry. No settings
are imported from legacy files by opening this editor. Trees without JSON
retain their existing editor until coordinated cutover.


The JSON workflow/layout writer APIs accept an observed absent file. Workflow
callers pass =:expected nil= explicitly; layout callers retain the actual read
snapshot with its nil revision. Missing observations are refused. If another
client creates the file first, the shared transaction reports a conflict and
preserves its bytes. This prepares first publication; fresh-root JSON defaults
and legacy reader retirement remain part of coordinated cutover.

* Measure interactive latency

Enable =M-x org-glance-perf-mode= and use =org-glance-transient= normally.
Open =*Messages*= to compare materialize, overview and LLM timings. Toggle the
mode again to remove its instrumentation.

Each numbered command reports inclusive stage times, call counts, synchronous
elapsed time, minibuffer interaction, work excluding that interaction, and GC
time/count. Nested stage times overlap. The transient-to-command total includes
key selection and prompt wait. Logs contain function names and timing values.
The event-loop marker reports scheduling after return, including log output;
screen painting and provider readiness require separate measurement. LLM menu
preparation and terminal creation have separate command traces; first model
output requires provider tracing.

Picker preparation temporarily allows 64 MiB between garbage collections and
restores the caller's GC policy before entering the minibuffer. Equal serialized
metadata shares decoding within one committed SQLite read; the next read gets
fresh metadata.

Run =make bench-interactive= to measure the materialize command with automatic
selection and a fresh editor on disposable synthetic stores.

See [[file:proposals/2026-11-08-interactive-cache-timing.done.org][interactive timing measurements]].

** SQLite reader reuse

Cache reads retain up to 16 SQLite connections in least-recently-used order.
Each operation starts and ends its own checked read transaction. Nested reads
use independent connections; staging reads use temporary connections. Missing or replaced files retire the
old reader; failed reads retire their connection before reporting the error.
Connections close at Emacs exit. To release one graph's readers explicitly:

#+begin_src emacs-lisp
(org-glance-cache:close-readers org-glance-graph)
#+end_src

Pass no argument to release all readers. Active readers finish their operation
before closing. Equal-record decoding remains local to each read snapshot.
Run =make bench-readers= to measure committed UI point reads and connection
opens on disposable synthetic stores.

** Benchmark commands and tiers

=eask run command bench= and =make bench= run all four harnesses. Each harness
also has a named command:

| Workload | Make target | Eask command |
|----------+-------------+--------------|
| Graph construction, SQLite UI reads, compatibility reads, overview, recovery | =make bench-graph= | =eask run command bench-graph= |
| Plain/crypt editor open, warm lookup and save | =make bench-material= | =eask run command bench-material= |
| Materialize command with automatic selection and a fresh editor | =make bench-interactive= | =eask run command bench-interactive= |
| Warm committed UI point reads | =make bench-readers= | =eask run command bench-readers= |

The default store tiers are 1,000 and 10,000 headlines. =OG_BENCH_QUICK=1= selects
1,000 headlines and 100 point lookups; =OG_BENCH_LARGE=1= adds 100,000 headlines.
The material harness uses graph/history shapes 10/1, 50/12 and 100/40; quick
selects 10/1 and large adds 500/80. =OG_BENCH_SAMPLES= selects repeat count.
=OG_BENCH_SIZES= accepts positive comma-separated sizes for focused experiments.

#+begin_src sh
OG_BENCH_QUICK=1 make bench
python3 tools/bench.py readers --baseline HEAD~1 --quick --samples 7 --pairs 3
OG_BENCH_QUICK=1 make podman-bench
#+end_src

The Python driver compiles production code extracted from the requested Git
commit and from the current working tree, then runs the same current harnesses
against both. It verifies the loaded library locations. Its JSON records source
revisions, runtime, raw samples, work counters, ratios and fingerprint equality.
Use =--pairs= for independent process pairs in alternating revision order.
Collection runs before each sample; preparation and fingerprint observers run
outside its timing window. Each revision's fingerprint must stay stable in every
round and process. A cross-revision
fingerprint difference is reported separately from latency.

The work-counter arm fails inside ERT. Latency samples support review against
commit baselines; =docs/invariants.org= records accepted measurements. Investigate
an unexplained regression before committing.

Existing compatible caches can be measured with
=python3 tools/bench.py interactive --directory /path/to/org-root= or
=OG_BENCH_DIRECTORY=/path/to/org-root make bench-readers=. Commit comparisons use
disposable stores. Graph and material workloads always use disposable stores.

** Timing registration and test environment

Customize =org-glance-perf-commands=, =org-glance-perf-stages= and
=org-glance-perf-continuations= to choose traced function symbols. Option changes
refresh enabled advice. Plugins append their own names without loading provider
libraries:

#+begin_src emacs-lisp
(org-glance-perf:register
 :commands '(my-command my-menu)
 :stages '(my-resolver)
 :continuations '(my-menu))
#+end_src

Registration accepts symbols before definition and collapses duplicates. Core
owns its timing names; the LLM plugin owns provider, menu and terminal stages.
The start report and trailing reports lie outside the command's time/GC window.

Development environment options use =OG_= names: =OG_CONFIG_BENCH=,
=OG_CONFIG_READ_FIXTURE=, =OG_CONFIG_VECTORS=, =OG_CONFIG_SETTINGS_VECTORS=,
=OG_TEST_XVFB= and =OG_OVERVIEW_FROZEN=. The =GLANCE_CONFIG_= aliases remain
accepted by the config fixture adapter for the daemon's existing test targets.
An enabled configuration timing case skips when its optional fixture is absent.
