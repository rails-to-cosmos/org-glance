#+TITLE: Write path and storage audit — org-glance
#+DATE: 2026-11-08

Status: *audit; compatible write-path fixes implemented 2026-11-09* · companion to [[file:2026-07-06-performance-audit.org][the 2026-07-06 performance audit]]

Every audit so far has measured reads.  Reads are now fast: the point read is
0.21 ms and flat ([[file:2026-11-08-performance-gate-measures-the-live-path.done.org][the performance gate]]).  This one measures the WRITE path and
the STORE, where the remaining cost sits.  Measured on Linux, Emacs 31.1.90,
synthetic stores from =org-glance-test:with-graph=, plus the real 7,119-headline
=~/sync/views= store read-only.

The profiles below are the 2026-11-08 baseline. The compatible implementation
and remaining coordinated work are recorded below.

* Two numbers that frame it

| Path                      | Cost            | Real store at 7,157 |
|---------------------------+-----------------+---------------------|
| =graph:add=, N=200        | 14.9 ms/headline | —                  |
| =graph:reindex=, N=300    | 23.2 ms/headline | ≈ 165 s            |

Canonical payload on the real store is 72.1 MB.  The store is 2.1 GB across
76,050 inodes.

* Theme 1 — the write path reparses each headline four times

=elp= over =graph:add=, 200 headlines in two batches:

| Function                        | Calls | Per headline |  Elapsed |
|---------------------------------+-------+--------------+----------|
| =graph:add=                     |     2 |              | 2.989 s  |
| =cache--after-append=           |     2 |              | 2.481 s  |
| =headline--from-string=         |   800 |          4.0 | 1.536 s  |
| =cache--prepare-headline=       |   200 |          1.0 | 1.462 s  |
| =graph--reparse-blob=           |   400 |          2.0 | 0.666 s  |
| =graph:get-content=             |   200 |          1.0 | 0.317 s  |
| =version--observe-directories=  |  1000 |          5.0 | 0.162 s  |

The same shape, worse, under =reindex= at N=300: =--from-string= 1,200 calls
(4.0), =--reparse-blob= 900 (3.0), =get-content= 600 (2.0),
=version--observe-directories= 1,800 (6.0).

Three facts follow.  The synchronous family projection is 83% of an insert and
74% of a reindex.  The writer reads back and reparses the blob it just wrote.
The 2026-07-06 audit's item D collapsed "4 thunk reparses → one
=--content-facts= pass" on the read side; the write side carries the multiplier
in this baseline.

* Theme 2 — directory inventories are the hot path, over a polluted tree

Invariant 41 makes immutable family directories the search authority, so
freshness costs a =readdir= pass.  The write profile shows five to six
=version--observe-directories= calls per headline.  What they walk, on the real
store:

| Component                                  |   Size |  Inodes |
|--------------------------------------------+--------+---------|
| Headline payload (=data.org= + =meta.json=) | 72.1 MB |  30,452 |
| =.agent-home= provider caches (23 dirs)     |  1.3 GB |  12,377 |
| =sessions/= in total                        |      —  |  14,043 |
| =cache/= (git-ignored)                      |  219 MB |       9 |
| =archive/=                                  |  126 MB |      —  |
| Whole store                                 |  2.1 GB |  76,050 |

Each additional version costs three inodes: its event directory, =data.org=
and =meta.json=; family and shard directories are shared across versions.  The deepest family holds 514
versions, so one headline owns over a thousand inodes.  The =.agent-home= trees belong to the Glance agent sandbox. Immutable-family
inventory already stops before these trees; legacy-family discovery previously
recursed through arbitrary descendants. The implementation below bounds that
discovery to the ID layout.

The =inventory_directory= table already exists in the cache, so the checkpoint
side of this is built.

* Theme 3 — one headline, four representations

A 118-byte headline, one version:

| Representation                     | Bytes | Derived | In git |
|------------------------------------+-------+---------+--------|
| =data.org=                         |   118 | no      | yes    |
| =meta.json=                        |   262 | no      | yes    |
| =meta/seg-*.jsonl= record          |   331 | yes     | yes    |
| =cache/org-glance.sqlite3= share   | ~3900 | yes     | no     |
| =cache/property-index.eld= share   |   128 | yes     | no     |

Git-tracked: 711 B for 118 B of content.  On disk with 4 KiB blocks and five
inodes: ≈ 12 KiB.

=meta.json= is 2.2× the content it describes, and =version=, =event=,
=producer= and an empty =parents= account for roughly 90 of its 262 bytes.  The
WAL record is derived in full (invariant 5) yet git-tracked, and invariant 35
already schedules its retirement at the stage-5 cutover.

Real =cache/= holds three databases: =org-glance.sqlite3= 48 MB (6.7 KB per
headline against 3 MB of total projection payload), =glance-index.sqlite3= 62 MB
beside a 61 MB un-checkpointed WAL, and =glance.sqlite3= 42 MB untouched since
2026-10-19 — the former shared cache invariant 35 imports without modifying and
nothing retires.

* Where the wins are

Ranked by measured payoff against risk.

1. *One parse per headline on the write path.*  Carry one =--content-facts= pass
   from =graph:add= through metadata, blob write and family projection.  Target
   15 → 4 ms insert, 23 → 6 ms reindex, ≈ 165 → 45 s on the real store.  The
   pattern is already proven by audit item D.
2. *Never read back what was just written.*  =get-content= plus =--reparse-blob=
   during insert and reindex re-derive what the caller holds.
3. *Share preparation across the insert batch.*  =--prepare-headline=,
   =--prepare-family=, =--payload-observation= and =--version-metadata= run once
   per headline. Projection already commits once per batch; preparation still
   duplicated parsing and scanned the batch repeatedly by ID.
4. *Demote the directory walk to the repair path.*  A generation counter per
   family directory, checked against =inventory_directory=, lets a read skip
   =readdir= entirely and keeps the walk for repair. This requires coordinated
   writer participation under invariant 41.
5. *One file per version.*  Fold =meta.json= into a header on =data.org=, or
   append both to a per-headline log.  Saves ≈ 30,000 inodes on the real store.
   Touches invariants 39–41 and the Glance interop contract.
6. *Move provider session homes out of =data/=.* Glance sandbox-side, into
   a private cache location: 1.3 GB and 12,377 inodes leave the store; sandbox
   HOME mappings, credentials and isolation require a coordinated migration.
7. *Cache hygiene.*  Retire =glance.sqlite3= after import, checkpoint
   =glance-index.sqlite3-wal=, and account for 6.7 KB per headline across a
   15-column =headline= and a 10-column =headline_event=.
8. *Retire the WAL at stage-5.*  331 B per headline of derived data leaves git,
   and compaction stops minting a multi-MB git object per run.

* Compatible implementation — 2026-11-09

Items 1–3 share operation-local source analysis across graph writes, reindex and
material saves. Exact source bytes, raw SHA-256, parsed metadata and content facts
travel together; a successful publication supplies its own payload receipt.
New inserts perform one canonical parse per headline inside the writer, zero
payload disk reads and two family observations. Caller construction remains a
separate parse. Reindex performs one parse, one payload read and one family
observation per headline; contexts reset every 500 headlines.

Receipts validate size, mtime, ctime, inode and device before reuse; symlinks
always read afresh. Namespace changes and changed source identities invalidate
observations. Local publication, legacy migration and pruning invalidate the
family explicitly. Returned content strings and history lists remain owned by
the caller. Fault tests cover hook corruption, restored mtimes, inode replacement
and external events during an operation.

Verified, digest-matching non-leaf payload observations reuse parseability;
current leaves still parse metadata. Missing or incompatible derived cache state
falls back to source analysis. Batch preparation indexes IDs once, and maintenance
reads reuse existing idle connections without introducing a retained reader.

Item 4 retains directory inventories as search authority. Per-operation validated
observations remove repeated walks; family discovery visits only short-ID roots
and canonical shard/ID directories, including a short ID beside its sharded
siblings. A persistent generation counter requires all independent writers to
participate before it can replace inventories.

Items 5 and 8 remain coordinated protocol work under invariants 35 and 39–41:
canonical two-file events and the compatibility WAL remain in force. Item 6
belongs to Glance's =src-query/Glance/Agent/Sandbox.hs=, lines 63–65
([[https://gitlab.com/rails-to-cosmos/glance/-/blob/d0e4eeef8187fbdca51f9ff63dfcec820f0df813/src-query/Glance/Agent/Sandbox.hs#L63][sandbox HOME mapping]]), including private credentials and mount policy.

Item 7's read-only inspection of =~/sync/views= finds 49,762,304 bytes in the
private SQLite file, including 2,711,552 free bytes. Its largest tables are
=headline_event= (9,900,032 B), =org_headline= (7,225,344 B),
=headline_projection= (5,586,944 B) and =headline_payload_observation=
(5,361,664 B), plus indexes and source/inventory tables. There are 15,318 events
for 7,157 families; serialized current projection payloads total 3,669,792 B.
These distinct representations explain the footprint comparison. The former
shared database remains untouched under invariant 35; foreign WAL checkpointing
belongs to the owning Glance connection lifecycle.

Three alternating compiled process pairs against =ef1e388= measure inserts
1,651→1,016 ms and reindex 1,518→570 ms at N=100; plain/crypt saves fall
22.1/23.4→8.9/9.0 ms. Cold property fill improves 470→432 ms. These are
synthetic warm-filesystem measurements; the real store was inspected read-only.
Validation and paired measurements are recorded in
[[file:../invariants.org::*Write-path analysis contracts][Write-path analysis contracts]].

* Out of bounds

- *Content-addressed blobs.*  =meta.json= already carries =contentSha256=.  Store
  blobs by digest in a sharded CAS and let versions reference it.  Identical
  content across versions dedupes, and the 514-version family stops paying 514
  copies of near-identical text.  The single largest structural storage idea
  here.
- *Pack cold versions.*  Git's own answer: fold cold families into one
  append-only pack plus an index, leaving loose files at the recent frontier.
  Fits invariant 40's append-only history and removes the inode problem without
  touching semantics.
- *SQLite as authority.*  The end state invariant 35 points at: blobs plus one
  committed database, with the third representation gone.
- *Incremental reindex.*  Skip families whose content hash is unchanged, making
  reindex O(changed) rather than O(N).

* Method

=elp-instrument-package= over =org-glance-graph=, =-headline=, =-cache=,
=-version=, =-core= and =-property-index=, one batched =graph:add= of 200 and one
=graph:reindex= of 300 in separate batch processes.  Footprints from =find= and
=du= on a built 1,000-headline synthetic store and read-only on =~/sync/views=.
Cache composition from =sqlite3= in =mode=ro= and =PRAGMA page_count=.  Segment
counts read from =meta/MANIFEST=, whose generation numbers are not a count:
the real store holds eight live segments.

** Findings

1. *Observation revalidation is linear in a family's version count, and the
   contract ladder stops an order of magnitude below the live store.*  The proof
   table holds =data.org= and =meta.json= per version, and
   =version--observation-current-p= re-stats every entry on each reuse —
   [[https://github.com/rails-to-cosmos/org-glance/commit/113814b][113814b]],
   =src/data/org-glance-version.el= line 358.  Measured proof size and
   revalidation cost:

   | Versions | Proof paths | =current-p= ms | Observe reuse ms |
   |----------+-------------+----------------+------------------|
   |        8 |          18 |           0.92 |             0.95 |
   |       32 |          66 |           3.58 |             3.49 |
   |      128 |         258 |          13.78 |            12.28 |
   |      512 |        1026 |          54.45 |            50.16 |

   Proof size is 2V + 2 and cost is linear.  =~/sync/views= holds one family of
   514 versions, its runner-up at 33, so that headline pays about 54 ms of
   =stat= per observation and about 109 ms per save at two observations, growing
   with each further save.  Reuse still beats re-walking, which read and parsed
   those same files.  =virtual-save-family-work-contract= exercises depths 1, 8
   and 32 and asserts call counts, which hold constant in V, so this cost may
   grow unbounded while the gate stays green; at depth 32 it measures 3.58 ms.
   Open as [[file:2026-11-09-bound-family-revalidation.proposed.org][Bound family
   revalidation]].  Item 4's generation counter is the structural answer and now
   carries a measured ceiling.
2. *The remaining write cost has moved.*  =cache--after-append= holds 54% of an
   insert and 35% of a reindex, from 83% and 74% in the audit's baseline, and
   stays the largest single block at one call per batch.  =graph:put-content= is
   35% of an insert at 2.3 ms per headline, which is payload inode creation and
   belongs to item 5.  A later write-path pass starts here.
3. *=tools/bench.py= measures the working tree for the current label* —
   [[https://github.com/rails-to-cosmos/org-glance/commit/113814b][113814b]],
   =tools/bench.py= lines 38-43 — and samples =dirty= once before measuring,
   line 182, without warning or refusing.  A =bench.py readers= run during this
   review died with =Invalid read syntax= against a concurrently written
   =org-glance-cache.el=.  A dirty or mid-write tree measures code that no
   revision holds.

** Corrected in the audit above

Two of the audit's own earlier statements were wrong and the implementation pass
amended them; the review confirms the amendments.

- *Three inodes per additional version, against the audit's original five.*
  =~/sync/views= holds 15,223 event directories and 30,447 files below them, so
  each version costs its directory plus =data.org= plus =meta.json=.  Family,
  shard and =versions= directories are shared, 14,552 inodes for 7,120
  families.
- *Immutable inventory stops at the =versions= root.*  =version:inventory= lists
  it with non-recursive =f-directories=, so an inventory pass never descends
  into a provider session tree.  Legacy family discovery carried the recursion,
  and =family-inventory-stays-within-the-id-layout= now plants a provider
  lookalike and asserts the scan skips it.
