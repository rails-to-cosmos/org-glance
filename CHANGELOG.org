** Changed
- README: adds installation and capture examples and moves the full feature
  reference to =docs/guide.org=.
- Tag metrics now live in writer-owned =meta/tag-metrics-seg-*.eld= files, so
  concurrent machines preserve both counter increments without editing one
  =config/tag-metrics.eld=; existing singleton data migrates on graph open.
- =C-c @= in a material buffer now calls =org-glance-relations:references=
  (was =org-glance-material:references=); the command moved to the new
  =org-glance-relations= bridge library, above both material and table.
- =meta/.gitattributes= gives the =union= merge driver the WAL's own files by
  name -- =headlines.jsonl= and =seg-*.jsonl= -- where a =*.jsonl= glob also
  handed it the notification family and =COMPLETIONS.jsonl=.  An existing
  store's file is left alone (write-if-absent).
- A fold reads a notification source WHOLE only where the poll says bytes may be
  owed; a drained generation costs a stat and a bounded hash.  Folding one line
  beside five drained 1 MiB generations: 48.5 ms -> 5.5 ms, 5,263,573 bytes
  hashed -> 20,663.
- The fold folds 18,000 distinct ids in 73 ms where it took 5.0 s: the
  first-sighting set is a hash table.
- Rotation reuses the verdict the pass's own read left, so a generation is
  hashed once per rotation instead of twice.
- Material =C-c #= is the only crypt key, dispatching on context: region ->
  wrap it; sealed buffer -> unseal; point inside a plaintext block -> unwrap
  it; decrypted buffer outside every block -> seal back, forgetting the
  password (refused with unsaved edits); plaintext headline -> encrypt the
  whole body.
- The content hash ignores the =LOGBOOK= drawer, so clocking in and out no
  longer invalidates the property index or any hash-guarded projection.
- Table =g= now resets the view to the filter it was opened with: the =/=
  substring filter and a narrow-to-marked view are cleared (marks survive).
  Reloads behind an edit still preserve them.
- =C-c @= in a material buffer opens ONE relation table (outgoing edges and
  referrers merged) instead of the outgoing-only table.  Scoped layouts key on
  =relations= and pair on anchor tag > row tag, so entries saved under the old
  =refs= / =backlinks= scopes no longer match.
- Tag config is one file per tag, =config/tags/<tag>.org=: optional =#+TITLE:=
  label and =#+TODO:= cycle pragmas, body from the first =*= heading is the
  capture entry.  A freshly stubbed file carries only the capture template
  (=* %?=); pragmas are opt-in overrides.  Legacy =config/tags.org= auto-splits
  on graph open, backed up as =tags.org.bak=.  =org-glance-tag-config-file=
  replaced by =org-glance-tag-config-dir=; =C= (Configure) prompts for the tag.
- *Core no longer depends on =agnostic-llm= (and so never pulls in

** Fixed
- Clock entries and state notes no longer count as headline content: =CLOCK:=

- Materializing with =-d= while the headline is already open and sealed decrypts
  that buffer; it errored in the view it was run from.
- Table layouts and other =.eld= sidecars are written atomically: a crash
  mid-write leaves the previous file whole.
- =M-x revert-buffer= in a material buffer keeps it materialized: saves still
  index, crypt stays wired, managed drawer keys stay out of the buffer.
- An external WRITE no longer resurrects a tombstoned id whose blob still
  lingers before compaction: =org-glance-graph:refresh-external= skips it, the
  tombstone winning (invariant 30).  A WRITE still ingests a genuinely unknown
  id and re-derives a live one.
- A spent =EXTERNAL-<generation>.jsonl= is MOVED to
  =meta/spent/= and kept.  Six rounds of holes in the check that licensed
  the delete each cost a tombstone nothing could get back; a wrong answer costs
  disk now, and the file is there to be moved back -- the =.jsonl= alone, since
  it then carries no cursor and the next fold takes it whole.  A retired
  generation is out of the fold's reach until somebody does that, and NOTHING
  prunes =meta/spent/=: =M-x org-glance-graph:clear-spent-external= empties it,
  or =rm -r= over the directory.
- A generation this Emacs cannot READ is no longer taken for a fully folded
  one.  An unreadable file and an absent one both left an empty buffer, so the
  check compared 0 with 0, said every byte was folded and destroyed a file it
  had never read -- measured over a generation carrying an unfolded tombstone:
  readable, spared; =chmod 000=, unlinked.  A directory or a dangling symlink
  wearing a generation's name is refused the same way.
- =meta/EXTERNAL.jsonl=, its generations, their cursors and =meta/spent/= are
  git-ignored; an existing store's =.gitignore= gains the lines on the next
  open.  IGNORING DOES NOT UNTRACK: a store that already committed them keeps
  syncing them until =git rm --cached '.org-glance/meta/EXTERNAL*'= is run once.
- KNOWN COST of that ignore: a daemon on one machine no longer notifies an Emacs
  on another (=git add -f= keeps one tracked on purpose).
- Moving a retired =EXTERNAL-<gen>.jsonl= back into =meta/= strands its old
  =.cursor= under =meta/spent/= and an =EXTERNAL-<gen>.cursor= in =meta/=; both
  are inert.
- An outside delete survives a fold: the fold reads from a byte cursor
  (=meta/EXTERNAL.cursor=) and rewrites =EXTERNAL.jsonl= never.
- =EXTERNAL.jsonl= grows by rotation: renamed to =EXTERNAL-<gen>.jsonl= once a
  fold takes it past =org-glance-graph-external-max-bytes=, two DRAINED
  generations kept, a line landing in a just-rotated file still folded.
- The rotation cap bounds the file again: rotation reads the offset the fold
  took, where re-stating the size afterwards deferred the rename indefinitely
  under a live writer.
- =meta/EXTERNAL.cursor= records TWO sha1s beside its offset -- the last 4 KiB
  before it, and the whole prefix -- so a hand edit, a botched rotation or a
  restore costs a re-fold.  A cursor written before this change reads as 0.
- A fold READS THE NOTIFICATION FILE ONCE, verifying the cursor's prefix and
  recording the new digest out of that one buffer.
- An outside write replacing =EXTERNAL.jsonl= at its own length is folded: the
  poll verifies the last 4 KiB before the offset and that the offset ends a
  line, where a size comparison saw nothing.
- Rotation retires an =EXTERNAL-<gen>.jsonl= only once that generation's own

- A rotated generation rotation refuses to retire has its cursor dropped, so the
  next fold takes it whole.
